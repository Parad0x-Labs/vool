## Decisions taken

1. Keep all original base source byte-identical. Add an opt-in laboratory module/CLI; no production route, installer, release or build change. Smaller than wiring new ingress into today's chat frontdoor.
2. Use `VOOL_DROP_FIT=1`; absent/other values refuse before home or relay creation. Separate local CLI is the prototype interface; real inbox UI is later.
3. Vendor the pinned MIT candidate unchanged with complete notices. Review remains open. Use an existing SSD Node binary and existing pinned Python environment; no package installation needed unless an actual dependency is missing.
4. Shared SSD directory is the only demo transport. Relay contains ciphertext, no cloud account, socket listener or spending. Durable local queues provide restart recovery; hosting and network admission are later.
5. One Drop is one selected packet/conversation scope with one file and one bounded task. Whole-Drop forget revokes its session and derivatives; independent per-message sessions/group ratchets are later.
6. A creates an invite, B consumes it with a pinned A identity and returns a handshake; A accepts with pinned B identity. A can then queue the packet while B is closed. Link decoding and pin confirmation are explicit; no private key in the link. Invites and delivery are capped at seven days.
7. Chunk the selected file through the existing 64 KiB session API; enforce 10 MiB before send and after assembly, exact byte count/digest and no sender-chosen output path. Large resumable streaming storage is later.
8. Default task is selected-file SHA-256, computed from fresh bytes only after local approval. Incoming text is displayed as data and never parsed into commands. General model/shell tasks need planner, sandbox and consent integration later. Reject extra permissions and paid requests.
9. Reuse real durable forget authority and existing sweep/read APIs. No fake success when a reader retains content; incomplete cleanup stays a failed demo step and a blocker. Disable automatic learning/admission to reduce the carrier surface.
10. Run one nice'd affected check at a time; wait for load >8 or a release build/smoke process. No full suite or packaging. Preserve equal base/head existing-test denominators and every failure; baseline failures are not repaired here.
11. Task-specific commit identity is `sls_0x <240776969+Parad0x-Labs@users.noreply.github.com>` as directly requested and required by this base's AGENTS.md. Commits stay local and contain the board task trailer only.
12. Preserve all inputs and existing worktrees. New status and raw evidence live beside the supplied research; scratch homes/caches belong to this task. FIT.md is committed before any implementation; PROTOTYPE.md will record actual outcomes and missing release work.
13. Actual semantic readers use hashed scope IDs while other stores use raw IDs. The incomplete-cleanup control exposed a barrier mismatch. The isolated prototype publishes a home-wide fence first; incomplete cleanup withholds the whole scratch home. Completed revocation targets the unique Drop ID in carriers. A narrower raw/hashed scope authority mapping needs review before production. No existing reader or release code is changed.
14. Create a real chat namespace on verified admission, without profile or receipt grants. Empty Drops need that owner too for expiry. Retain an untrusted handshake draft only for recovery; admit it only after the matching delivery exists in the verified native inbox. Recover native initial outbox metadata and already-materialized files after a cut. General streaming resume and arbitrary external effects remain later.
15. Consume public invite links after authenticated acceptance and discard expired native prekeys on the owner's sweep. Independent identity pins remain required; possessing a link alone never grants execution. The local CLI is the explicit approval controller; remote payloads cannot call it.
16. The erasure experiment deliberately seeds actual VOOL stores with synthetic records and a hash-vector control, proves each reader can serve them first, then checks those same readers after erasure. This proves carrier lifecycle, not embedding quality, autonomous task behavior or physical SSD sanitization. No model calls are needed.
