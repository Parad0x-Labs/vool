# 오류와 오류 코드

무언가가 실패하면 VOOL은 무슨 일이 있었는지, 이미 무슨 일이 일어났을 수 있는지, 다음에 무엇을
해야 하는지를 쉬운 말로 알려 줍니다. 모든 실패에는 고정된 코드도 있습니다. 코드는 오류 아래의 기술
세부 정보, 명령줄(`wallet_export_refused: …`), API 응답에서 찾을 수 있습니다. 이 페이지는 오류를
읽는 방법을 설명합니다. [오류 사전](../ERROR_BOOK.md)은 모든 코드를 설명합니다.

## 오류 읽기

다시 시도하기 전에 세 가지를 확인하세요.

1. **무슨 일이 있었는지.** 메시지입니다. 메시지에는 내부 경로나 비밀 정보가 절대 들어 있지
   않습니다.
2. **이미 무슨 일이 일어났을 수 있는지.** 대부분의 거부는 무언가를 보내거나 바꾸기 전에 멈추며,
   메시지가 그렇다고 알려 줍니다. 요청이 나간 뒤의 시간 초과처럼, 어떤 실패는 동작이 끝났는지 알
   수 없습니다. 그러면 메시지는 결과를 알 수 없다고 말하고, 다시 시도하기 전에 확인하라고
   요청합니다. 결제는 실수로 두 번 보내지지 않습니다. 같은 결제를 두 번째로 보내면
   [`wallet_duplicate_payment`](../ERROR_BOOK.md#wallet-duplicate-payment)로 거부됩니다.
3. **다음에 무엇을 할지.** 구체적인 한 단계입니다.

의미는 코드에 담겨 있습니다. 403이나 429 같은 HTTP 상태는 요청이 도중에 어떻게 되었는지만 말해
주며, 서로 다른 두 거부가 같은 상태를 가질 수 있습니다. 상태가 아니라 코드를 읽으세요.

## 코드와 오류 사전

코드는 절대 이름이 바뀌지 않으며, 다른 의미로 재사용되지도 않습니다.
[오류 사전](../ERROR_BOOK.md)은 앱 자체의 오류 카탈로그에서 생성되므로, 그 안의 코드, 메시지,
다음 단계는 앱이 보여 주는 것과 정확히 같습니다. 모든 코드에는 자체 섹션이 있습니다. 받은 코드
그대로 페이지에서 검색하거나, 사전의 주소 뒤에 `#`과 밑줄을 하이픈으로 바꾼 코드를 붙여 섹션에
링크하세요. 예: [`wallet_broadcast_failed`](../ERROR_BOOK.md#wallet-broadcast-failed).

가장 자주 보게 될 코드:

| 코드 | 제목 | 이미 일어났을 수 있는 일 |
| --- | --- | --- |
| [`permission_denied`](../ERROR_BOOK.md#permission-denied) | 권한 거부됨 | 아무것도 바뀌지 않았습니다. |
| [`provider_unavailable`](../ERROR_BOOK.md#provider-unavailable) | 공급자에 연결할 수 없음 | 아무것도 보내지 않았습니다. |
| [`provider_exhausted`](../ERROR_BOOK.md#provider-exhausted) | 공급자 한도 도달 | 요청이 공급자에게 도달했습니다. |
| [`timeout`](../ERROR_BOOK.md#timeout) | 시간 초과 | 알 수 없음: 다시 시도하기 전에 확인하세요. |
| [`cancelled`](../ERROR_BOOK.md#cancelled) | 취소됨 | 알 수 없음: 일부가 이미 실행되었을 수 있습니다. |
| [`credential_failure`](../ERROR_BOOK.md#credential-failure) | 저장된 자격 증명을 읽을 수 없음 | 아무것도 보내거나 바꾸지 않았습니다. |
| [`unknown`](../ERROR_BOOK.md#unknown) | 예기치 않은 오류 | 알 수 없음: 다시 시도하기 전에 확인하세요. |
| [`wallet_quote_mismatch`](../ERROR_BOOK.md#wallet-quote-mismatch) | 승인이 더 이상 미리보기와 일치하지 않음 | 아무것도 서명하거나 보내지 않았습니다. |
| [`wallet_broadcast_failed`](../ERROR_BOOK.md#wallet-broadcast-failed) | 결제를 전파할 수 없음 | 알 수 없음: 다시 시도하기 전에 결제 상태를 확인하세요. |
| [`wallet_duplicate_payment`](../ERROR_BOOK.md#wallet-duplicate-payment) | 이미 제안되었거나 보낸 결제 | 새로 보낸 것은 없습니다. 이전 결제가 기록에 있습니다. |

## 오류와 다른 결과

VOOL은 다음을 서로 구분하며, 문구도 그렇게 구분합니다.

* **오류.** 무언가가 실패했습니다. 코드와 메시지가 무엇이 실패했는지, 무엇을 해야 하는지
  알려 줍니다.
* **내 답을 기다리는 중.** 권한 요청이나 결제 승인이 열려 있습니다. 아무것도 실행되지 않았으며,
  내가 답할 때까지 아무것도 실행되지 않습니다. [권한](../concepts/permissions.md)을 참고하세요.
* **지출 한도나 가격 안전장치에 의해 중단됨.** 거부는 공급자에게 연락하기 전에 일어나며, 메시지는
  공급자에게 요청했다는 암시를 절대 하지 않습니다.
  [지출 한도와 가격 안전장치](../guides/spending-limits.md)를 참고하세요.
* **취소됨.** 나 또는 VOOL이 끝나기 전에 멈췄습니다. 일부가 이미 실행되었을 수 있으므로, 다시
  시작하기 전에 무엇이 바뀌었는지 확인하세요.
* **여기서는 불가능.** 이 빌드나 이 컴퓨터로는 할 수 없으며, 메시지가 무엇이면 할 수 있는지 알려
  줍니다. VOOL이 처음부터 끝까지 확인할 수 없는 방식의 결제 제안, 또는 설치되지 않은 선택적 추가
  구성 요소가 그런 경우입니다.
* **결과를 알 수 없음.** 전파가 끝내 확인되지 않은 결제처럼, 동작이 끝났을 수도 있고 아닐 수도
  있습니다. 먼저 상태를 확인하세요. VOOL은 무작정 다시 결제하는 일이 절대 없습니다.

## 자체 코드가 있는 오류

VOOL의 몇몇 영역은 실패가 일어난 화면에서 자체의 짧은 코드로 실패를 설명하며, 이 코드는 오류
사전에 없습니다. 첨부 파일(예: 너무 큰 파일, 붙여넣은 파일에서 발견된 자격 증명), 앱 업데이트,
프로젝트 폴더, 모델 선택, 지출 한도, 연락처, 플러그인과 스킬, 음성 입력, 저장된 데이터, 버그
보고가 그렇습니다. 이 메시지들도 같은 방식으로 무슨 일이 있었고 무엇을 해야 하는지 알려 줍니다.
[채팅과 첨부 파일](../concepts/chats-and-attachments.md),
[업데이트와 마이그레이션](updates-migration.md),
[버그 보고와 개인정보](../trust/bug-reporting.md)를 참고하세요.

## 모르는 코드

오류 사전에 없는 코드는 이 버전의 VOOL에서 나온 것이 아닙니다. 어느 버전이 그 코드를 보여
주었는지 확인한 다음, 그 버전의 [오류 사전](../ERROR_BOOK.md)에서 검색하세요. 이 버전에서 나온
코드가 맞다면, 코드를 적힌 그대로, 그리고 응답에 참조값(`fault-`와 열두 글자)이 있었다면 그것도
함께 보고하세요. VOOL이 분류할 수 없는 실패는 추측한 원인이 아니라
[`unknown`](../ERROR_BOOK.md#unknown)으로 표시됩니다.
[버그 보고와 개인정보](../trust/bug-reporting.md)를 참고하세요.

설치, 모델, 플랫폼 문제는 [문제 해결](../help/troubleshooting.md)을, 채팅, 메모리, 지갑을 되찾는
방법은 [백업 및 복구](../help/backup-and-recovery.md)를 참고하세요.
