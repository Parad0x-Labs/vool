# 업데이트와 마이그레이션

## 업데이트 방식

0.7.5부터 VOOL은 스스로 업데이트합니다. '스스로 온라인 연결'이 켜져 있으면 알림을 표시하고 한 번 눌러 새 버전을 설치합니다. Mac에서 0.7.4나 0.7.3에서 업데이트하는 경우: '스스로 온라인 연결'(설정 > 개인정보와 권한)을 켜고 '업데이트 확인'을 한 번 누르세요. Linux에서 0.7.4 이하, 또는 Mac에서 0.7.2 이하인 경우: 0.7.7을 내려받아 현재 버전 위에 설치하세요. 채팅과 설정은 앱 바깥의 프로필에 저장됩니다.

'스스로 온라인 연결'이 켜져 있으면 VOOL은 시작할 때와 하루에 한 번 새 버전을 확인하며,
'업데이트 확인'을 누르지 않아도 알림을 표시합니다. 꺼져 있으면 VOOL은 아무것도 가져오지 않으며
헤더에 **업데이트 확인 꺼짐**이 표시됩니다.

서명된 업데이트 패키지는 자동 롤백이 있는 검증된 파이프라인을 거칩니다.

1. **다운로드** — 서명된 매니페스트와 대조해 검증합니다.
2. **단계적 설치** — 새 버전을 기존 버전 옆에 설치합니다.
3. **마이그레이션** — 데이터를 새 저장소 버전으로 옮깁니다. 마이그레이션이 실패하면 데이터가 이전
   버전으로 복원되고 앱이 그 버전으로 다시 시작합니다: *'데이터가 이전 버전으로
   복원되었습니다.'*
4. **상태 점검** — 이전 버전을 내리기 전에 새 버전이 제대로 서비스할 수 있음을 증명해야 합니다.
5. **교체** — 원자적으로 이루어지며, 이전 버전은 롤백 대상으로 보관됩니다.

Linux에서는 tarball 설치도 같은 방식으로 업데이트됩니다. 새 버전은 실행 중인 버전 옆에 설치되고,
`current`가 한 번에 새 버전으로 전환됩니다. 새 버전이 정상이 아니면 VOOL이 스스로 이전 버전으로
되돌아갑니다. 수동 **Roll back**은 Mac과 소스 설치에서 제공되지만, Linux tarball 설치에는 아직
없습니다.

어느 단계든 실패하면 앱은 원래 상태 그대로 남습니다. 실패 메시지는 해당 단계
(`verification_failed`, `insufficient_disk_space`, …)를 밝히며, 단계마다 고유한 복구 안내 문장이
있습니다.

## 데이터 호환성

* 프로필, 채팅, 영수증, 설정은 앱 번들 밖에 있으므로, 앱을 교체해도 데이터가 교체되는 일은 절대
  없습니다.
* 로컬 저장소는 **다운그레이드** 시 열기를 거부합니다. 더 새로운 VOOL이 쓴 데이터베이스를 더 오래된
  VOOL이 조용히 읽지 않습니다. 알 수 없는 저장소 구조를 추측하면 데이터가 손상되므로, 그렇다고
  알리고 거부합니다. 새 데이터를 읽으려면 더 새로운 버전을 다시 설치하세요.
* 업데이트로 설치된 파일과 업데이트 상태 자체가 영수증과 함께 프로필 아래에 기록되므로, '어떤
  버전이 내 데이터를 건드렸는지'를 나중에 확인할 수 있습니다.

## 베타 채널

현재 릴리스 라인은 **베타**입니다([릴리스 상태](../trust/release-status.md) 참고). 업데이트는
고정된 게시자 키로 서명되며 설치 전에 확인됩니다. macOS 앱 자체는 ad-hoc 서명만 되어 있고 Apple
공증을 받지 않았으므로, 새 버전을 처음 실행할 때 macOS가 확인을 요청할 수 있습니다.
