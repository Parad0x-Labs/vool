# 언어, 접근성, 기록

## 인터페이스 언어

VOOL의 인터페이스는 여러 언어로 제공됩니다. 언어 선택은 표시 방식의 문제일 뿐입니다. 권한 결정,
지출 권한, 오류 코드는 **설계상 언어와 무관합니다**. 번역된 오류 메시지가 영어로 된 원래 결정을
넓히거나 좁히는 일은 절대 없습니다.

## 접근성

* 주요 흐름을 위한 키보드 단축키([키보드 단축키](shortcuts.md) 참고).
* 문서와 앱 화면의 밝은 표시와 어두운 표시. 시스템 설정을 따르며 직접 바꿀 수도 있습니다.
* 오류는 색만이 아니라 텍스트로 표시됩니다. 파괴적인 동작에는 한 번의 실수 클릭이 아니라 항상
  명시적인 확인이 필요합니다.

## 활동

활동 보기는 VOOL이 한 일의 전체 기록입니다. 입력과 결과가 포함된 도구 호출, 내가 허락하거나 거부한
승인, 영수증이 포함된 결제가 담깁니다. 안전장치에 의해 멈춘 턴은 멈춤과 그 안전장치를 보여 줍니다.
거부는 빠진 것이 아니라 기록된 이벤트입니다.

## 영수증

돈과 지출에 관련된 동작은 **영수증**을 씁니다. 무엇이 제안되었고, 무엇이 승인되었고, 무엇이
보내졌고, 무엇이 정산되었는지를 남깁니다. 알 수 없는 결과는 알 수 없음으로 기록되며, 성공이나
실패로 꾸며 서술되는 일은 절대 없습니다. 그래서 *'다시 시도하기 전에 상태를 확인하세요'*라는
안내를 실제로 따를 수 있습니다. 영수증이 결제가 실제로 어떤 상태인지 알려 주기 때문입니다.

## 모델 검증 상태

VOOL은 모델이 **말한** 것과 런타임이 **증명한** 것을 구분합니다.

* 도구 결과는 실행 기록과 함께 기록됩니다. 파일, 결제, 데이터에 관한 답변의 주장은 그 기록에
  묶이며, 뒷받침되지 않는 주장은 보류됩니다.
* 영수증에는 검증 상태가 있습니다. 이 빌드에서 어떤 레인이 실험적이거나 검증할 수 없으면, 증명을
  암시하지 않고 상태가 그렇다고 밝힙니다.

개념은 [영수증](../concepts/receipts.md)을, 실패를 분류하는 방식은 [오류](errors.md)를
참고하세요.
