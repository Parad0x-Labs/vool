# 연락처

연락처 목록은 VOOL이 주소를 다시 입력하라고 요청하는 대신 사용할 수 있는, 구조화된 로컬
주소록(사람, 그 사람의 엔드포인트와 결제 별칭)입니다. 주소록은 결제와 메시지에 쓰이므로, 주소록
편집은 **보호됩니다**. 검토되고, 확인되고, 기록됩니다.

## 보호되는 편집

저장된 연락처를 바꾸는 것은 두 단계 흐름입니다.

1. **검토** — 변경이 준비되어 표시됩니다. 내가 연 뒤에 항목이 바뀌었다면(다른 창, 다른 기기),
   변경은 *'검토 후에 변경되었습니다. 다시 검토하세요. 아무것도 바뀌지 않았습니다.'*라는 메시지와
   함께 거부됩니다.
2. **확인** — 변경은 검토 화면에서 내 PIN이나 암호를 입력해야만 확정됩니다.

모든 거부 메시지는 **아무것도 저장되거나 바뀌지 않았다**고 분명히 밝힙니다. 실제로 아무것도 바뀌지
않았기 때문입니다. PIN은 받아들여졌지만 저장 자체가 실패했다면, 메시지가 바로 그렇게 알려 줍니다.
PIN은 받아들여졌으니, 확인이 만료되기 전에 다시 저장하라는 것입니다.

## 보호 장치

* 연락처마다 한 번에 하나의 변경만 가능하며, 대기 중인 변경의 수에는 제한이 있습니다.
* 연락처를 삭제해도 기록이 조용히 다시 쓰이지 않습니다. 삭제된 연락처에 대한 참조는
  *'그 연락처는 삭제되었습니다'*로 보고되며, 조용히 다른 대상으로 다시 해석되는 일은 절대
  없습니다.
* 가져오기는 절대 일부만 적용되지 않습니다. 원본을 읽을 수 없었다면 아무것도 가져오지 않은
  것입니다.

## 이렇게 설계한 이유

오타가 난 결제 주소는 되찾을 수 없는 돈입니다. 검토 단계는 어떤 모델 턴도, 어떤 일괄 편집도, 어떤
오래된 창도, 사람이 결과 항목을 정확히 확인하지 않은 채 'Alice'가 누구를 가리키는지 바꿀 수 없게
하려고 있습니다.
