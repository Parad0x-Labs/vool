# 추가 기능 검사

추가 기능은 둘러보기, 살펴보기, 설치를 서로 분리해 둡니다. 검사는 특정 바이트에 대한 설명일 뿐, 안전 보장도, 게시자 보증도, 실행 권한도, 지갑 승인도 아닙니다.

탐색은 앱과 함께 제공되는 VOOL 스킬 75개(그중 22개는 VOOL 도구를 쓰며, 이 도구는 VOOL이 이미 제공하는 것을 좁힐 뿐입니다)를 포함해 VOOL 자체 스킬을 먼저 보여 주고, 그다음에 검토된 카탈로그 추가 기능을 보여 줍니다. 스킬 코덱스는 VOOL 팀 스킬을 편집자 추천과 주목할 스킬보다 위에, 맨 먼저 보여 줍니다.

## VOOL이 만든 스킬: 로컬 검사

VOOL이 만든 스킬 75개는 앱 안에 들어 있으며, 각각 VOOL 자체 디렉터리에서 SHA-256으로 고정되고 VOOL이 릴리스될 때 검토됩니다. 이 스킬들의 경우 **이 스킬 추가**는 VOOL의 로컬 검사만 실행합니다. 키도, 검사 사용량도, 네트워크 요청도 필요 없습니다.

1. VOOL은 앱 자체 사본에서 스킬과 라이선스를 읽고, 그 SHA-256이 고정값과 일치하지 않으면 거부합니다(*이 VOOL 스킬의 파일이 VOOL과 함께 제공된 사본과 일치하지 않아 추가하지 않았습니다.*).
2. VOOL의 로컬 검사는 스킬에 위험한 지시가 있는지 읽고 결과를 보여 줍니다. 깨끗한 결과는 **추가하고 켜기**로 추가할 수 있습니다. 검사가 표시한 항목은 그 정확한 버전에 대해 내가 따로 명시적으로 동의해야 합니다. **거부**를 누르면 버려집니다.
3. 그다음 설치는 다른 스킬과 같은 수명 주기를 따릅니다. 정확히 그 파일이 설치되고, 검증되고, 켜집니다. 설치된 스킬은 불러올 때마다 고정된 SHA-256과 대조되며, 파일이 바뀌면 사용할 수 없게 됩니다.

로컬 검사는 고정된 바이트를 정적으로 읽는 것이며, 안전이나 답변 품질을 보장하지 않습니다. 다른 제작자의 스킬은 절대 이 경로를 거치지 않습니다.

## 공개 스킬

고정된 리비전의 공개 GitHub 스킬을 고르고 그 내용을 내려받는 것을 승인합니다. VOOL은 이 기기에서 그것을 검사합니다. 켜진 검사기 플러그인이 없으면 페이지에서 검사가 이 기기 안에서만 이루어졌다고 설명합니다. 이 경로에는 검사기 키가 필요 없습니다.

켜진 검사기 플러그인이 있으면, 검사를 요청할 때 그 플러그인도 공개 스킬 내용을 받습니다. 이 경우 그 서비스의 사용량이 소모될 수 있습니다. 로컬 채팅, 비공개 작업 공간 파일, 그 밖의 자격 증명은 제출되지 않습니다. 키를 저장하거나 추가 기능을 열어도 연결 테스트나 검사 요청은 일어나지 않습니다. 요청을 자동으로 다시 시도하지 않습니다.

발견 사항을 읽고 설치는 따로 수락합니다. 보고서 검증에는 완전한 적용 범위와 유효한 발견 사항이 필요합니다. 통과한 보고서에는 발견 사항도 정책 위반도 없습니다. 따로 제시되는 위험 수락은 검토된 버전에 묶이며, 보고서를 바꾸거나 더 많은 접근 권한을 주는 일은 절대 없습니다. 만료된 검토, 바뀐 준비 영역 바이트, 링크, 충돌하는 대상 폴더는 거부됩니다. 영수증은 설치된 배포본 전체에 묶입니다. 파일이 바뀌면 실행 시 사용할 수 없게 됩니다. 스킬 지침은 통째로 삽입되거나, 프롬프트 예산에 들어가지 않으면 명시적으로 생략됩니다.

## 선택 사항인 검사기

원격 검사기는 선택 사항입니다. 켜진 검사기 플러그인이 없으면, 이 기기에서 실행되는 VOOL 자체 검사가 스킬을 설치할 수 있는지 결정합니다. 이전 버전에서는 대신 원격 검사가 필요했습니다.

검사기를 추가하려면, 제작자의 검사기 플러그인을 플러그인 섹션에서 설치하고, 내 키를 저장하고, 접근 권한을 검토한 다음 켜세요. 그 선언에는 명시적인 연결 테스트용 경로와 요청된 검사용 경로가 적혀 있으며, 공유되는 네이티브 플러그인 전송 계층이 그 요청을 보냅니다. VOOL에는 기본 제공 검사기 클라이언트도, 중앙의 검사기 키 설정도 없으며, VOOL 자체 검사기 플러그인도 제공하지 않습니다. 이전 VOOL에서 저장한 Eyebrow 키는 이 컴퓨터에 남지만 사용되지 않습니다. ID `vool-plugin-eyebrow`와 `vool-plugin-usepod`는 예약되어 있으며, 이 중 하나를 내세우는 다른 패키지는 검토 전에 거부됩니다.

이 기기에서 실행되는 VOOL 자체 검사는 항상 실행됩니다. 검사기 플러그인의 보고서는 그 옆에 추가됩니다. 둘 중 하나라도 문제를 찾으면 설치가 막히며, 플러그인 보고서는 검사한 정확한 내용을 밝혀야 합니다. 검사기 플러그인은 절대 혼자서 설치를 승인할 수 없습니다.

켜진 검사기의 키가 없거나 거부되면 분명하게 실패합니다. VOOL은 요청된 원격 검사를 통과한 로컬 결과로 조용히 바꾸는 일이 절대 없습니다. 시간 초과, 서비스 오류, 리디렉션, 너무 큰 응답, 불완전한 보고서는 설치를 수락되지 않은 상태로 둡니다. 시간이 초과된 요청도 서비스 사용량을 소모했을 수 있습니다.

## 실행 가능한 패키지와 스토어 검토

플러그인은 텍스트 전용 스킬 가져오기와는 별도로, 로컬 폴더나 고정된 공개 GitHub 패키지의 전체 검토를 거칩니다. 설치할 때 패키지 코드는 실행되지 않으며 꺼진 상태로 유지됩니다. 스토어 플러그인에는 기존의 서명된 영수증과 배포본 전체 다이제스트도 필요합니다. 켜려면 도구, 효과, 정확한 호스트, 자격 증명 슬롯, 함께 묶인 서버를 다루는 별도의 접근 권한 시트가 필요합니다.

실행 코드는 호출될 때 자신이 선언한 키만 받습니다. 다른 플러그인의 슬롯, 소유자의 유료 모델 키, 지갑 서명·한도·승인·영수증 권한은 읽을 수 없습니다. 그 출력은 계속 신뢰하지 않는 것으로 취급됩니다. 바이트가 바뀌면 동의가 철회되고, 끄면 호출이 멈춥니다. 지원되지 않는 격리 방식에서는 실행이 거부됩니다. 실행 시 제한은 [플러그인 작성](../../../guides/plugin-authoring.md)을 참고하세요.

VOOL이 플러그인 기록을 읽을 수 없으면, 기록이 없는 팩은 VOOL과 함께 제공된 것을 제외하고 스킬 제공을 멈추며, 손상된 파일은 새 파일 옆에 보관됩니다. 켜기와 끄기 선택을 읽을 수 없으면, 다시 켤 때까지 모든 플러그인이 꺼진 것으로 간주됩니다.

## 로컬 API와 전송

`GET /api/addons`는 인벤토리를 읽습니다. `POST /api/addons`의 변경 작업에는 소유자 로컬 접근, JSON, 같은 출처의 브라우저 요청, 작업별로 정해진 필드가 필요합니다. 플러그인 켜기/끄기와 수명 주기 창구(`POST /api/plugins/enable`, `POST /api/plugins/lifecycle`)에도 같은 JSON 및 같은 출처 규칙이 적용됩니다. 공개 소스 다운로드는 정확한 리비전과 크기가 제한된 검증된 blob을 사용합니다. 네이티브 서비스는 선언된 공개 HTTPS 호스트를 요구하고, TLS를 검증하고, 확인된 공개 주소를 고정하고, 리디렉션을 거부하고, 응답 크기를 제한하며, 플러그인이 꺼지면 멈춥니다.

로컬의 가짜 HTTPS 서비스로 유료 호출 없이 전송과 오류 처리를 검증할 수 있습니다. 이것으로 실제 서비스의 안정성, 과금, 모델 능력, 다른 애플리케이션 안에서의 설치까지 입증되지는 않습니다. 이런 부분은 별도로 검증해야 합니다.
