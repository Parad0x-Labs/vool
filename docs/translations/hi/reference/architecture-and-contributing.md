# आर्किटेक्चर और योगदान

## एक पेज में आर्किटेक्चर

VOOL एक लोकल-फ़र्स्ट डेस्कटॉप रनटाइम है, जिसका कोर सर्व किया जाता है:

```text
┌──────────────────────────────────────────────┐
│ Native window / browser console              │
│  (served pages; the console you use)         │
├──────────────────────────────────────────────┤
│ Served runtime (local HTTP API)              │
│  routing → tool execution → answers          │
├───────────────┬──────────────┬───────────────┤
│ Local models  │ Cloud lanes  │ Wallet (opt)  │
│ (Ollama etc.) │ (your keys)  │ pilot lanes   │
├───────────────┴──────────────┴───────────────┤
│ Records: receipts, ledgers, fault registry   │
│ Local storage (SQLite under your profile)    │
└──────────────────────────────────────────────┘
```

कोड इन सिद्धांतों को लागू करता है:

* **डिफ़ॉल्ट रूप से स्थानीय; क्लाउड आपकी कुंजी से।** क्लाउड लेन सिर्फ़ आपके क्रेडेंशियल और आपकी ऊपरी सीमाओं के साथ मौजूद होती हैं।
* **हर फ़ैसले का एक ही प्राधिकार।** अनुमतियों, खर्च और नेटवर्क से बाहर जाने वाले ट्रैफ़िक, हर एक का एक ही ज़िम्मेदार अनुबंध है; विफलताएँ उसी सीमा पर वर्गीकृत होती हैं जिसकी वे ज़िम्मेदारी हैं।
* **बताएँ कि क्या विफल हुआ।** अज्ञात नतीजे अज्ञात के रूप में दर्ज होते हैं; अस्वीकृतियाँ बताती हैं कि क्या नहीं हुआ; पिन किया गया मॉडल कभी चुपचाप बदला नहीं जाता।
* **सब कुछ दर्ज।** टूल कॉल, स्वीकृतियाँ, भुगतान और अपडेट आपकी प्रोफ़ाइल में रसीदें लिखते हैं।

## डेवलपर सेटअप

```bash
git clone https://github.com/Parad0x-Labs/vool.git
cd vool
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest tests -q            # the suite
```

प्लेटफ़ॉर्म से जुड़े नोट, पूरे टूलचेन का ढाँचा और रिलीज़ की शर्तें रिपॉज़िटरी के इंजीनियरिंग दस्तावेज़ों में हैं (रिपॉज़िटरी रूट में `docs/`; गहरे आंतरिक विवरण इस सार्वजनिक दस्तावेज़ साइट का हिस्सा नहीं हैं)।

## दस्तावेज़: एक प्रामाणिक स्रोत

ये दस्तावेज़ **एक** स्रोत से बनाए जाते हैं: इस रिपॉज़िटरी का `docs/` फ़ोल्डर (GitBook ढाँचा, रिपॉज़िटरी रूट पर `.gitbook.yaml`)। सार्वजनिक दस्तावेज़ साइट इसी से बनती है। दस्तावेज़ों पर काम करने के लिए:

```bash
python3 tools/docs/build_docs.py --src . --out docs-build --base /docs
python3 tools/docs/check_docs_build.py docs-build /docs
python3 -m http.server -d docs-build 8000   # local preview
```

त्रुटि संदर्भ (`ERROR_BOOK.md`) और लोकलाइज़ेशन हैंडऑफ़ मैनिफ़ेस्ट **रनटाइम की अपनी रजिस्ट्रियों से बनाए जाते हैं** — इन्हें दोबारा बनाएँ, कभी हाथ से संपादित न करें:

```bash
python -m tools.generate_error_book
python -m tools.generate_localization_handoff
```

अगर बनाई गई फ़ाइलें अपनी रजिस्ट्रियों से अलग हो जाएँ, तो एक केंद्रित परीक्षण बिल्ड को विफल कर देता है।

## योगदान

* छोटे, समीक्षा किए गए बदलाव; दस्तावेज़ों का हर दावा रिलीज़ हुए कोड से मेल खाना चाहिए।
* स्थायी कोड और पहचानकर्ता बनाए रखें — वे बिल्ड से ज़्यादा समय तक टिकते हैं।
* कभी किसी प्राधिकार को चुपचाप न बढ़ाएँ: नई अनुमति, खर्च का रास्ता या बाहर जाने वाली लेन एक डिज़ाइन बदलाव है, पैच नहीं।
* बीटा की सीमाएँ दर्ज की जाती हैं, छिपाई नहीं जातीं — अगर आपको कोई बिना दर्ज की गई सीमा मिले, तो वह दस्तावेज़ों में एक बग है।
