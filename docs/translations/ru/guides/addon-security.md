# Проверки дополнений

«Дополнения» разделяют просмотр, проверку и установку. Сканирование описывает конкретные байты;
это не гарантия безопасности, не одобрение издателя, не разрешение на выполнение и не одобрение кошелька.

«Обзор» сначала показывает собственные навыки VOOL, включая 75 навыков VOOL, поставляемых с приложением (22 из них
используют инструменты VOOL, которые лишь сужают то, что VOOL уже предлагает), затем проверенные дополнения из каталога. «Кодекс навыков» показывает сначала навыки команды VOOL, а под ними — выбор редакции и рекомендуемые навыки.

## Навыки, созданные VOOL: локальная проверка

75 навыков, созданных VOOL, поставляются внутри приложения; каждый закреплён по SHA-256 в собственном каталоге VOOL и
проверяется при выпуске VOOL. Для них **Добавить этот навык** запускает только локальную проверку VOOL: без ключа,
без квоты сканирований и без сетевых запросов.

1. VOOL читает навык и лицензию из собственной копии приложения и отклоняет их, если их SHA-256 не
   совпадает с закреплённым (*This VOOL skill's file doesn't match the copy that came with VOOL, so it was not added.*).
2. Локальная проверка VOOL читает навык в поисках рискованных инструкций и показывает результат. Чистый результат
   можно добавить кнопкой **Добавить и включить**; всё, что она отметила, требует вашего отдельного явного согласия для
   этой конкретной версии. **Отклонить** отбрасывает навык.
3. Затем установка идёт по тому же жизненному циклу, что и у других навыков: точные файлы устанавливаются,
   верифицируются и включаются. Установленный навык сверяется со своим закреплённым SHA-256 при каждой
   загрузке; изменённый файл делает его недоступным.

Локальная проверка — это статическое чтение фиксированных байтов, а не гарантия безопасности или качества ответов.
Навыки от других авторов никогда не идут этим путём.

## Публичные навыки

Выберите публичный навык с GitHub на фиксированной ревизии и одобрите загрузку его содержимого. VOOL проверяет
его на этом устройстве с помощью `core/local_scan.py`. Если включённого плагина-сканера нет, страница объясняет,
что проверки остались на этом устройстве. Для этого пути ключ сканера не нужен.

Включённый плагин-сканер при запросе сканирования также получает содержимое публичного навыка. Это
может расходовать квоту его сервиса. Локальные чаты, личные файлы рабочего пространства и другие учётные данные
не отправляются. Сохранение ключа и открытие «Дополнений» не выполняют ни проверки соединения, ни запроса на сканирование.
Автоматических повторов запросов нет.

Читайте результаты и принимайте установку по отдельности. Проверка отчёта требует полного охвата
и корректных результатов. Успешный отчёт не содержит находок и нарушений политики. Отдельно предлагаемое
принятие риска привязано к проверенной версии; оно никогда не меняет отчёт и не даёт дополнительного доступа.
Просроченные проверки, изменённые байты подготовленной загрузки, ссылки и конфликтующие целевые папки отклоняются.
Квитанции привязывают весь установленный дистрибутив. Изменённые файлы отзывают доступность во время выполнения.
Указания навыка вставляются целиком или явно опускаются, если не помещаются в бюджет промпта.

## Необязательные сканеры

Удалённый сканер необязателен. Если ни один плагин-сканер не включён, собственная проверка VOOL на этом устройстве
решает, можно ли установить навык; более ранние версии вместо этого требовали удалённого сканирования.

Чтобы добавить сканер, установите плагин-сканер от его автора через раздел «Плагины», сохраните свой
ключ, проверьте доступ и включите его. Его объявление называет путь для явной проверки соединения
и путь для запрошенного сканирования, а эти запросы выполняет общий собственный транспорт плагинов.
В VOOL нет встроенного клиента сканера или центральной настройки ключа сканера, и VOOL не предлагает собственного
плагина-сканера. Сохранённый ключ Eyebrow из более старой версии VOOL остаётся на этом компьютере и не используется.
Идентификаторы `vool-plugin-eyebrow` и `vool-plugin-usepod` зарезервированы; другой пакет, который заявляет
один из них, отклоняется ещё до проверки.

Собственная проверка VOOL на этом устройстве выполняется всегда. Отчёт плагина-сканера добавляется рядом с ней:
если любая из них находит проблему, установка блокируется, а отчёт плагина должен называть точное
проверенное содержимое. Плагин-сканер никогда не может сам одобрить установку.

Включённый сканер с отсутствующим или отклонённым ключом явно завершается ошибкой. VOOL никогда молча не заменяет
запрошенное удалённое сканирование успешным локальным результатом. Тайм-ауты, ошибки сервиса, перенаправления,
слишком большие ответы и неполные отчёты оставляют установку непринятой. Запрос, завершившийся по тайм-ауту,
мог всё равно израсходовать квоту сервиса.

## Исполняемые пакеты и проверка магазина

Плагины проходят полную проверку пакета из локальной папки или закреплённого публичного пакета GitHub, отдельно от
импорта навыков, состоящих только из текста. Установка не запускает код пакета и оставляет его отключённым. Плагины
из магазина также требуют существующей подписанной квитанции и полного дайджеста дистрибутива. Включение требует
отдельного листа доступа, охватывающего инструменты, эффекты, точные хосты, слоты учётных данных и встроенные серверы.

Исполняемый код при вызове получает только свои собственные объявленные ключи. Он не может читать слоты другого
плагина, оплачиваемые ключи моделей владельца или полномочия кошелька на подпись, лимиты, одобрения и квитанции.
Его вывод остаётся недоверенным. Изменённые байты отзывают согласие; отключение останавливает вызовы. Неподдерживаемая
изоляция отказывает в выполнении. Ограничения среды выполнения описаны в разделе [Создание плагинов](../../../guides/plugin-authoring.md).

Если VOOL не может прочитать свои записи о плагинах, пакеты, о которых у него нет записи, перестают предлагать навыки, кроме
поставляемых с VOOL, а повреждённый файл сохраняется рядом с новым. Если VOOL не может прочитать
ваши выборы «включено» и «отключено», каждый плагин считается отключённым, пока вы снова не включите его.

## Локальный API и транспорт

`GET /api/addons` читает перечень. Изменения через `POST /api/addons` требуют локального доступа владельца,
JSON, браузерных запросов того же источника и полей, специфичных для действия. Точки включения/отключения и жизненного цикла плагинов
(`POST /api/plugins/enable`, `POST /api/plugins/lifecycle`) применяют то же правило JSON и
того же источника. Загрузки публичных исходников используют
точные ревизии и ограниченные по размеру проверенные блобы. Собственные сервисы требуют объявленных публичных хостов HTTPS,
проверяют TLS, закрепляют разрешённые публичные адреса, отклоняют перенаправления, ограничивают ответы и останавливаются, когда
плагин отключён.

Локальные поддельные сервисы HTTPS позволяют проверить транспорт и обработку ошибок без платных вызовов. Они не
подтверждают надёжность реального сервиса, выставление счетов, компетентность моделей или установку внутри других
приложений. Для этого нужна отдельная проверка.
