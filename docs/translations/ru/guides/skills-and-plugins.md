# Навыки и плагины

**Навык** — это упакованный набор инструкций для повторяющейся задачи. **Плагин** добавляет новые
инструменты в среду выполнения.

## Встроенные и установленные извне

VOOL поставляется с **собственной библиотекой навыков** — навыками, которые идут вместе с самим приложением, — и,
в текущих сборках, с плагином **VOOL Database**. Вы также можете устанавливать собственные навыки и
плагины.

| | Встроенные (поставляются с VOOL) | Установленные извне |
| --- | --- | --- |
| Где находятся | Внутри приложения | В вашей папке плагинов (задаётся в настройках) |
| Обновления | Вместе с приложением | Когда вы обновляете пакет |
| Можно отключить | Да — по отдельности | Да — по отдельности |
| Дают разрешения | **Нет** | **Нет** |

Для обоих источников действуют два правила:

* **Навыки учат, но никогда не дают прав.** Объявленные навыком инструменты — это сигнал *сужения* (бюджет
  инструментов рабочего процесса), а не предоставление чего-либо. Контроллер разрешений не читает
  навыки.
* **Один перечень.** Каталог, который показывает консоль, и пакеты, которые загружает среда выполнения, — это
  один и тот же список. То, что навык есть в списке, не доказывает, что он загрузится: каждая запись содержит
  своё текущее состояние (доступен, отключён, не выполнено предварительное условие, недействительный контракт) и причину.

## Поиск навыков

Раздел «Навыки и плагины» сначала показывает собственные навыки VOOL. Во вкладке **Обзор** есть 53 готовых навыка
VOOL. Они только текстовые: каждый — это набор инструкций, поставляемый вместе с приложением, поэтому
«Обзор» показывает их без поиска в интернете. Навыки VOOL, которые используют инструменты VOOL, перечислены
на вкладке **Кодекс навыков**, где первыми идут навыки команды VOOL. Просмотрите навык, прежде чем
включать его.

## Состояния доступности

Навык может отображаться как недоступный с указанием типизированной причины: не выполнено предварительное условие (например,
навыку базы данных нужен включённый плагин базы данных), нужная возможность недоступна на этом компьютере,
контракт недействителен или навык отключён вами. Причины показываются для каждой записи, а отключение
действует для отдельной записи и сохраняется после перезапусков.

## Повторяющиеся идентификаторы

Если два пакета объявляют один и тот же идентификатор плагина (например, встроенный пакет и установленная копия),
встроенный сохраняется **детерминированно**, а отброшенная копия указывается в
каталоге — она никогда не перекрывается молча.

## Установка собственных

Устанавливайте из каталога в приложении или укажите VOOL собственную папку плагинов. Пакеты содержат
манифест (`plugin.json`), в котором объявлены их инструменты; манифест, чьи объявления разрешений не
соответствуют объявленному классу поведения, отклоняется при загрузке.

{% hint style="danger" %}
Проверьте весь пакет перед верификацией. Проверка — это свидетельство о конкретных байтах,
а не сертификат безопасности и не предоставление разрешений.
{% endhint %}

## Одобрение пакетов в v0.7

Верификация охватывает каждый файл и каталог пакета, включая исполняемые файлы обработчиков,
библиотеки, включённые в пакет, файлы фиксации версий зависимостей, справочные материалы, ресурсы и биты режима исполнения.
Добавление, удаление, переименование или изменение любого из них аннулирует одобрение. Символические ссылки,
жёсткие ссылки, специальные файлы, привилегированные режимы, нестабильные чтения и слишком большие дистрибутивы
отклоняются. Текущие ограничения захвата — 4 096 записей, 64 МиБ на файл и 128 МиБ
на пакет. Внутри пакета нет игнорируемых каталогов кэша или состояния.

Ранее сохранённые одобрения, основанные только на метаданных, в этой версии не активируют пакеты.
Проверьте полный дистрибутив, снова явно верифицируйте его, затем включите. Обновления остаются
отключёнными, пока не будут верифицированы и включены; одобрение никогда не переносится молча.
Управляемым дополнениям также нужна новая аутентифицированная проверка магазина, если старая квитанция
не привязывает полный дистрибутив; обычная верификация не может заменить эту квитанцию.

`requires` перечисляет установленные плагины-зависимости. Верификация фиксирует их рекурсивные дайджесты одобрения;
каждая зависимость уже должна быть верифицирована и включена. Изменённая, обновлённая, отключённая или
отозванная зависимость делает зависящие от неё пакеты недоступными, в том числе через кэшированные инструменты.
При допуске после хеширования повторно проверяется состояние включения и отзыва для всего захваченного замыкания.
Повторная верификация зависимости не одобряет молча её новые байты для родительского пакета: проверьте
и повторно верифицируйте также каждый родительский пакет. Каждый `approval_digest` привязывает дайджест своего пакета и одобрения
зависимостей, поэтому изменённая транзитивная зависимость меняет это одобрение, даже если собственные
файлы родительского пакета остались идентичными. Одобрение циклических зависимостей не может активироваться. Замыкание зависимостей
ограничено 64 пакетами.

Каждый зарегистрированный вызов снова проверяет состояние жизненного цикла и делает частные копии только для чтения
пакета и его закреплённого замыкания зависимостей. Контракт инструмента должен совпадать с
захваченным манифестом. Зарегистрированный обработчик запускается из этой копии; правка исходников
после захвата не может подменить этот обработчик или его встроенные файлы. Наблюдения за выполнением
включают дайджесты пакета, рекурсивного одобрения и зависимостей. Зарегистрированные пакеты требуют настоящей изоляции средствами ядра, даже если
локальный низкоуровневый вызывающий код выбрал более слабое переопределение.
Хосты без безопасного захвата дескрипторов без перехода по ссылкам или без изоляции средствами ядра отклоняют зарегистрированные
пакеты. Тайм-аут вызова ограничен диапазоном 1–300 секунд; группа процессов, принадлежащая вызову,
останавливается до удаления его копии для выполнения.

Храните постоянный вывод, кэши и журналы в `PLUGIN_SCRATCH`, а не рядом с исполняемым кодом.
Инструменты только для чтения не получают права на запись. Другие инструменты могут писать во временную папку, но не могут изменять
свою копию для выполнения. `VOOL_PLUGIN_DEPENDENCIES` — это JSON-сопоставление объявленных идентификаторов
зависимостей с захваченными каталогами зависимостей. Включайте другие сторонние библиотеки
и файлы фиксации их версий внутрь пакета; один лишь файл фиксации версий не подтверждает внешнее окружение.
Интерпретатор хоста и системные библиотеки остаются частью доверенной платформы и не
выдаются за проверенные байты сторонних пакетов. Эта проверка целостности
не сертифицирует поведение, не подтверждает произвольный код, загруженный извне одобренного
дистрибутива, не контролирует каждый внутренний эффект и не заменяет собственное одобрение кошелька.

## Создание навыка

Навык — это папка с файлом инструкций и любыми файлами, на которые он ссылается:

```text
my-skill/
├── SKILL.md
└── templates/
```

Создайте черновик в приложении (`skill.create` подготавливает его, ничего не активируя), проверьте его корректность, затем
установите, чтобы активировать, — три отдельных шага сделаны намеренно, чтобы создание навыка никогда не было неявным
изменением поведения. Каталог и формат создания навыков ещё дорабатываются к публичному
выпуску.
