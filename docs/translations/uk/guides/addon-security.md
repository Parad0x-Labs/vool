# Пошук навичок і перевірки Eyebrow

На сторінці «Навички та плагіни» чотири вкладки: **Огляд**, **Кодекс навичок**, **Мої додатки** і **Безпека**. «Огляд» спершу показує власні навички VOOL, зокрема 53 текстові навички VOOL, що постачаються із застосунком, потім перевірені додатки з каталогу, а також може знайти публічний репозиторій GitHub на закріпленій ревізії. «Кодекс навичок» показує спершу навички команди VOOL, а під ними — вибір редакції та рекомендовані навички. Пошук не враховує регістр і поширені роздільники; елементи вибору категорії та сортування звужують список. Джерело, ліцензію, ревізію та вимоги видно до завантаження.

## Перше використання

1. Збережіть ключ API Eyebrow у вкладці «Безпека», яка також доступна в розділі Налаштування → Ключі API. Ключем володіє наявне сховище облікових даних. Збереження не перевіряє зʼєднання й нічого не сканує; до Eyebrow явно звертається кнопка Test.
2. У вкладці «Огляд» виберіть навичку й схваліть завантаження її загальнодоступного вмісту та надсилання цього вмісту до Eyebrow. На це витрачається квота сканувань сервісу згідно з вашим тарифом. Автоматичних повторів не буває.
3. Прочитайте отриманий звіт. Сама лише успішна відповідь HTTP — ще не чистий результат. Цей початковий каталог дозволяє встановлення лише за повного звіту `pass`, без знахідок і без порушень політики. «Відхилити» видаляє підготовлене завантаження, не встановлюючи його.
4. Окремо прийміть встановлення. VOOL зберігає ліцензію, встановлює навичку через свій наявний життєвий цикл плагінів, верифікує точний перевірений пакет і вмикає навичку. Наявні дозволи й далі керують кожною дією, яку вона може запропонувати.

Сканування — це оцінка конкретних байтів постачальником, а не гарантія безпеки, сумісності чи якості відповідей. Включення до каталогу не є сертифікацією видавця.

## Межі

Вміст береться лише з публічних репозиторіїв GitHub на фіксованій 40-символьній ревізії, з файлами навички й ліцензії, закріпленими за SHA-256. У цій версії немає імпорту приватних репозиторіїв, розпакування архівів, скриптів встановлення та імпорту виконуваних плагінів чи плагінів MCP. До Eyebrow надсилається лише окремий файл SKILL.md; локальні чати, файли робочого простору, облікові дані й тексти ліцензій на сканування не передаються.

Завантаження залишаються неактивними до перевірки та прийняття. Локально автентифіковані квитанції привʼязують звіт до закріпленого вмісту. Встановлення відхиляє прострочені перевірки (24 години), змінені підготовлені файли й наявні цільові каталоги. Середовище виконання перевіряє стан життєвого циклу та перевірені байти, перш ніж додати керовану навичку до контексту моделі. Додані файли, символічні посилання або змінений вміст роблять її недоступною. Інструкції вставляються цілком або явно позначаються як пропущені через брак бюджету запиту; проскановані інструкції не обрізаються мовчки.

Ці перевірки не ізолюють шкідливого коду, який уже виконується від імені користувача операційної системи. Вони не поширюються на раніше встановлені вручну плагіни. Квитанція сканування не надає ні нових прав на виконання, ні повноважень гаманця.

## API та обробка збоїв

`GET /api/addons` повертає каталог і локальний статус без перевірки зʼєднання й без сканування. `POST /api/addons` підтримує `save_key`, `remove_key`, `test_key`, `scan`, `install` і `reject`. Запити, що змінюють стан, мають надходити через loopback, у форматі JSON і з браузера з того самого джерела; приймаються лише поля, що стосуються операції. Передані стороною виклику URL джерел і шляхи відхиляються.

Клієнт використовує запит Eyebrow v1 із вбудованим вихідним текстом навички за адресою `/v1/scan`, з автентифікацією bearer, фіксованим джерелом HTTPS, без переадресацій, з обмеженим розміром відповіді й без автоматичних повторів. `/v1/version` використовується для явної перевірки зʼєднання. Довідник API: https://eyebrow.cc/api/reference .

Типові типізовані збої:

| Код | Значення / що робити |
| --- | --- |
| `eyebrow_key_missing` / `eyebrow_unauthorized` | Збережіть або замініть ключ. |
| `eyebrow_quota` | Перш ніж повторювати, перевірте квоту сервісу. |
| `eyebrow_timeout` / `eyebrow_unreachable` | Автоматичного повтору немає; сканування, перерване через тайм-аут, усе одно може витратити квоту. |
| `eyebrow_invalid_report` / `eyebrow_no_coverage` | Свідчення неповні; нічого не вмикається. |
| `addon_source_changed` / `addon_changed` | Закріплені або перевірені байти відрізняються; не активуйте їх. |
| `review_untrusted` / `review_expired` | Перед встановленням отримайте нову перевірку. |
| `addon_already_installed` | Наявні файли збережено. Автоматичну заміну не реалізовано. |

## Поточні обмеження та перевірка

Немає автоматичного оновлення, імпорту довільних каталогів і процесу відновлення чи перевстановлення на місці для вже наявного зміненого пакета. Відновлення незавершеної перевірки після перезапуску застосунку в інтерфейсі недоступне. Нові рядки інтерфейсу поки що показуються англійською; повноти перекладів не заявлено.

Автоматичні тести перевіряють справжній життєвий цикл, завантаження навичок, обробники API та браузерний інтерфейс, який віддає сервер, з явно імітованими публічними завантаженнями й відповідями Eyebrow. Вони доводять поведінку середовища виконання та інтерфейсу, але не доступність живого Eyebrow і не компетентність моделі. Справжнє сканування з ключем і приймання нативного упакованого застосунку залишаються перевірками випуску. Для запуску цих тестів не потрібні ні ключ, ні виклик платного сервісу.
