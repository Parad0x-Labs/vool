# ארכיטקטורה ותרומה לפרויקט

## הארכיטקטורה בדף אחד

VOOL הוא סביבת הרצה למחשב, מקומית קודם כול, עם ליבה מוגשת:

```text
┌──────────────────────────────────────────────┐
│ Native window / browser console              │
│  (served pages; the console you use)         │
├──────────────────────────────────────────────┤
│ Served runtime (local HTTP API)              │
│  routing → tool execution → answers          │
├───────────────┬──────────────┬───────────────┤
│ Local models  │ Cloud lanes  │ Wallet (opt)  │
│ (Ollama etc.) │ (your keys)  │ pilot lanes   │
├───────────────┴──────────────┴───────────────┤
│ Records: receipts, ledgers, fault registry   │
│ Local storage (SQLite under your profile)    │
└──────────────────────────────────────────────┘
```

עקרונות שהקוד אוכף:

* **מקומי כברירת מחדל; ענן עם המפתח שלכם.** מסלולי ענן קיימים רק עם פרטי הגישה שלכם ועם
  התקרות שלכם.
* **סמכות אחת לכל החלטה.** להרשאות, להוצאות וליציאה לרשת יש לכל אחד חוזה אחד שאחראי עליו;
  כשלים מסווגים בגבול שאחראי עליהם.
* **אמרו מה נכשל.** תוצאות לא ידועות מסווגות כלא ידועות; סירובים אומרים מה לא קרה; מודל
  מוצמד אף פעם לא מוחלף בשקט.
* **הכול נרשם.** קריאות לכלים, אישורים, תשלומים ועדכונים כותבים קבלות תחת הפרופיל שלכם.

## הגדרת סביבת פיתוח

```bash
git clone https://github.com/Parad0x-Labs/vool.git
cd vool
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest tests -q            # the suite
```

הערות לפי פלטפורמה, המבנה המלא של כלי הפיתוח ושערי השחרור נמצאים בתיעוד ההנדסי של המאגר
(`docs/` בשורש המאגר; הפרטים הפנימיים העמוקים אינם חלק מאתר התיעוד הציבורי הזה).

## תיעוד: מקור קנוני אחד

התיעוד הזה נוצר ממקור **אחד**: התיקייה `docs/` של המאגר הזה (מבנה של GitBook, והקובץ
`.gitbook.yaml` בשורש המאגר). אתר התיעוד הציבורי נבנה ממנו. כדי לעבוד על התיעוד:

```bash
python3 tools/docs/build_docs.py --src . --out docs-build --base /docs
python3 tools/docs/check_docs_build.py docs-build /docs
python3 -m http.server -d docs-build 8000   # local preview
```

חומר העזר על השגיאות (`ERROR_BOOK.md`) ומניפסט ההעברה ללוקליזציה **נוצרים מהמרשמים של
סביבת ההרצה עצמה** — צרו אותם מחדש, ואף פעם אל תערכו אותם ידנית:

```bash
python -m tools.generate_error_book
python -m tools.generate_localization_handoff
```

בדיקה ממוקדת מכשילה את הבנייה אם הקבצים שנוצרו סוטים מהמרשמים שלהם.

## תרומה לפרויקט

* שינויים קטנים שעברו סקירה; כל טענה בתיעוד חייבת להתאים לקוד כפי שהוא שוחרר.
* שמרו על קודים ומזהים יציבים — הם נשארים יותר זמן מגרסאות.
* אף פעם אל תרחיבו סמכות בשקט: הרשאה חדשה, מסלול הוצאה חדש או ערוץ יציאה חדש לרשת הם שינוי
  תכנון, לא תיקון.
* מגבלות הבטא מתועדות, לא מוסתרות — אם מצאתם מגבלה שלא מתועדת, זה באג בתיעוד.
