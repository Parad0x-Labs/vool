# תצורה

## מיקומים

VOOL שומר את ההגדרות, הצ׳אטים, הזיכרון והרשומות שלו בתיקיית "runtime home" אחת:

| התקנה | תיקיית "runtime home" |
| --- | --- |
| יישום macOS | `~/Library/Application Support/VOOL/runtime` |
| התקנה מקובץ tar ל-Linux והתקנות מקוד המקור | `~/.vool_runtime` |
| Windows (ניסיוני, מקוד המקור) | `%LOCALAPPDATA%\VOOL` |

הגדרה של `VOOL_HOME` לפני הפעלת VOOL גורמת לו להשתמש בתיקייה הזו במקום. יומני ההפעלה
מדפיסים את התיקייה שבשימוש.

מפתחות **לא** נכתבים לקובצי הגדרות או ליומנים. הם נשמרים מוצפנים בקובץ פרטי גישה נפרד
בתיקיית "runtime home" הזו, שרק חשבון המשתמש שלכם יכול לקרוא; מפתחות ש-VOOL כבר שמר בצרור
המפתחות (Keychain) של macOS ב-Mac נשארים שם. ראו
[מודל האבטחה](../trust/security.md#מפתחות).

## הגדרות

שנו הגדרות ביישום תחת **הגדרות**. אלה ההגדרות שקובעות מה VOOL רשאי לעשות:

* **דגם** — המודל הפעיל, שקובע אם תור הוא "מקומי" או "ענן".
* **סביבת עבודה** — תיקיית הפרויקט שצ׳אט עובד בה; ראו [סביבות עבודה](../concepts/workspaces.md)
  כדי לדעת לאילו תיקיות אחרות VOOL יכול להגיע.
* **מצב פעולה** — נבחר בתפריט שליד תיבת ההודעה, לא כאן. מצב "ידני" שואל לפני כל שינוי;
  מצב "אוטומטי" מאפשר לעריכות ולפקודות יומיומיות לרוץ, ואילו מחיקה, דריסה, התקנה, הוצאת כסף
  ושינוי הגדרות עדיין שואלים. ראו [הרשאות](../concepts/permissions.md).
* **גישה לרשת וקריפטו** — שניהם נשארים כבויים עד שאתם מפעילים אותם.

ל-VOOL אין הגדרה של טלמטריית מוצר, כי הוא לא שולח טלמטריית מוצר.

## איפוס

צאו מ-VOOL והעבירו הצידה את תיקיית "runtime home". קבצי סביבת העבודה לא נפגעים; VOOL
מתחיל מחדש עם פרופיל חדש. המפתחות השמורים שלכם עוברים הצידה יחד איתה, לכן הוסיפו אותם שוב
ב**הגדרות ← מפתחות API**. מפתחות ששמורים בצרור המפתחות של macOS נשארים שם עד שתסירו אותם
ביישום "גישה לצרור מפתחות" (Keychain Access).
