# גילוי מיומנויות ובדיקות Eyebrow

לדף "מיומנויות ותוספים" יש ארבע לשוניות: **עיון**, **קודקס המיומנויות**, **התוספים שלי** ו**אבטחה**. "עיון" מציג קודם את המיומנויות של VOOL עצמו, כולל 53 מיומנויות VOOL של טקסט בלבד שמגיעות עם היישום, אחר כך את התוספים שנסקרו בקטלוג, והוא יכול לחפש מאגר GitHub ציבורי בגרסה (revision) מקובעת. "קודקס המיומנויות" מציג קודם את המיומנויות של צוות VOOL, מעל בחירות העורכים והמיומנויות המומלצות. החיפוש מתעלם מאותיות גדולות וקטנות וממפרידים נפוצים; פקדי הקטגוריה והמיון מצמצמים את הרשימה. המקור, הרישיון, הגרסה והדרישות גלויים לפני ההורדה.

## שימוש ראשון

1. שמרו מפתח API של Eyebrow בלשונית "אבטחה", שזמינה גם תחת הגדרות ← מפתחות API. מאגר פרטי הגישה הקיים הוא הבעלים של המפתח. השמירה לא בודקת את החיבור ולא סורקת שום דבר; "בדוק חיבור" פונה ל-Eyebrow במפורש.
2. ב"עיון", בחרו מיומנות ואשרו את הורדת התוכן הציבורי שלה ואת שליחת התוכן הזה ל-Eyebrow. זה צורך מהמכסה של השירות לסריקות, לפי התוכנית שלכם. אין ניסיונות חוזרים אוטומטיים.
3. קראו את הדוח שחזר. תגובת HTTP מוצלחת לבדה היא לא תוצאה נקייה. הקטלוג הראשוני הזה מתיר התקנה רק עם דוח `pass` מלא, בלי ממצאים ובלי הפרות מדיניות. "דחה" משליך את ההורדה שהוכנה בלי להתקין אותה.
4. אשרו את ההתקנה בנפרד. VOOL שומר על הרישיון, מתקין דרך מחזור החיים הקיים של התוספים, מאמת את החבילה המדויקת שנסקרה ומפעיל את המיומנות. ההרשאות הקיימות עדיין חלות על כל פעולה שהיא עשויה להציע.

סריקה היא הערכה של ספק חיצוני לגבי בייטים מסוימים, לא ערובה לבטיחות, לתאימות או לאיכות התשובות. הכללה בקטלוג היא לא הסמכה של המפרסם.

## גבולות

התוכן מגיע רק ממאגרי GitHub ציבוריים בגרסה קבועה בת 40 תווים, עם קובצי מיומנות ורישיון שמקובעים ב-SHA-256. אין בגרסה הזו תמיכה במאגרים פרטיים, בחילוץ ארכיונים או בסקריפטי התקנה, ואין מייבא לתוספי הרצה/MCP. רק קובץ ה-SKILL.md העצמאי נשלח ל-Eyebrow; צ׳אטים מקומיים, קבצים מסביבת העבודה, פרטי גישה ותוכן הרישיונות לא נשלחים לסריקה.

ההורדות נשארות רדומות עד הסקירה והאישור. קבלות שאומתו מקומית קושרות את הדוח לתוכן המקובע. ההתקנה דוחה סקירות שפג תוקפן (24 שעות), קבצים מוכנים ששונו ותיקיות יעד שכבר קיימות. סביבת ההרצה בודקת את מצב מחזור החיים ואת הבייטים שנסקרו לפני שהיא מוסיפה מיומנות מנוהלת להקשר של המודל. קבצים שנוספו, קישורים סימבוליים או תוכן ששונה הופכים אותה ללא זמינה. ההנחיות מוכנסות בשלמותן, או שנרשם במפורש שהן הושמטו כי תקציב ההנחיה לא הספיק; ההוראות שנסרקו לא נחתכות בשקט.

הבדיקות האלה לא מבודדות קוד זדוני שכבר רץ כמשתמש מערכת ההפעלה. הן לא חלות על תוספים שהותקנו ידנית קודם לכן. קבלת סריקה לא מעניקה שום הרשאת הרצה חדשה או סמכות על הארנק.

## API וטיפול בכשלים

`GET /api/addons` מחזיר את הקטלוג ואת המצב המקומי בלי בדיקת חיבור או סריקה. `POST /api/addons` תומך ב-`save_key`, `remove_key`, `test_key`, `scan`, `install` ו-`reject`. פעולות שמשנות משהו דורשות בקשות דרך loopback, ב-JSON ומדפדפן מאותו מקור (same-origin); רק שדות שמתאימים לפעולה מתקבלים. כתובות URL ונתיבים של מקור שהקורא מספק נדחים.

הלקוח משתמש בבקשת מקור המיומנות המוטמעת של Eyebrow v1 ב-`/v1/scan`, עם אימות bearer, מקור HTTPS קבוע, בלי הפניות, עם גודל תגובה מוגבל ובלי ניסיונות חוזרים אוטומטיים. `/v1/version` משמש לבדיקת החיבור המפורשת. תיעוד ה-API: https://eyebrow.cc/api/reference .

כשלים מסווגים נפוצים כוללים:

| קוד | משמעות / התאוששות |
| --- | --- |
| `eyebrow_key_missing` / `eyebrow_unauthorized` | שמרו את המפתח או החליפו אותו. |
| `eyebrow_quota` | בדקו את המכסה של השירות לפני ניסיון חוזר. |
| `eyebrow_timeout` / `eyebrow_unreachable` | אין ניסיון חוזר אוטומטי; סריקה שחרגה מהזמן עדיין עשויה לצרוך מהמכסה. |
| `eyebrow_invalid_report` / `eyebrow_no_coverage` | הראיות לא שלמות; שום דבר לא מופעל. |
| `addon_source_changed` / `addon_changed` | הבייטים המקובעים או שנסקרו שונים; אל תפעילו אותם. |
| `review_untrusted` / `review_expired` | קבלו סקירה חדשה לפני ההתקנה. |
| `addon_already_installed` | הקבצים הקיימים נשמרו. החלפה אוטומטית לא מומשה. |

## מגבלות נוכחיות ואימות

אין עדכון אוטומטי, מייבא קטלוגים שרירותי או תהליך תיקון/התקנה מחדש במקום עבור חבילה קיימת ששונתה. שחזור של סקירה ממתינה אחרי הפעלה מחדש של היישום לא זמין בממשק. מחרוזות ממשק חדשות מוצגות כרגע באנגלית כגיבוי; לא נטען שהתרגומים מלאים.

בדיקות אוטומטיות מפעילות את מחזור החיים האמיתי, את טעינת המיומנויות, את מטפלי ה-API ואת ממשק הדפדפן שמוגש, עם הורדות ציבוריות ותשובות Eyebrow שמדומות במפורש. הן מוכיחות את ההתנהגות של סביבת ההרצה ושל הממשק, לא את הזמינות של Eyebrow בפועל או את היכולת של מודלים. סריקה אמיתית עם מפתח, ובדיקת האישור של היישום המקורי הארוז, נשארות בדיקות שחרור. לא צריך מפתח או קריאה לשירות בתשלום כדי להריץ את הבדיקות האלה.
