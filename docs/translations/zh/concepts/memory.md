# 记忆

记忆是 VOOL 跨会话保留事实的方式。它以可读格式的文件存储在你的电脑上，位于 VOOL 的数据主目录中。

## 它记得有多好

在 LoCoMo 长对话基准测试中 150 道从未用过的题目上，VOOL 0.7 自带的记忆答对了 123 道（82.0%）。在同样题目的正面对比中，三者都由同一个模型作答，VOOL 答对 124 道（82.7%），OpenClaw 107 道（71.3%），Hermes 94 道（62.7%），而 VOOL 每题发送的 token 少 3.5 到 5.4 倍。每次运行都已公开：[记忆基准测试](https://github.com/Parad0x-Labs/vool/tree/main/docs/benchmarks)。

## 特性

* **存在磁盘上，公开可见。** 记忆就是你能读的文件。`MEMORY.md` 是可读的门面；它背后的事实保存在旁边的条目文件中。
* **本地。** 记忆不会同步到服务器。
* **每个 VOOL 主目录一个存储。** 记忆不按工作区划分——它为整个安装保存，所以它不是按项目隔离的边界。

## 管理记忆

你自己添加到 `MEMORY.md` 的笔记会被保留。VOOL 记录的事实要通过 VOOL 的遗忘操作来删除，而不是删除文件：遗忘会一步改写条目存储和镜像，并重新读取两者，确认文本已经消失。只删除 `MEMORY.md` 并不等于删除——条目文件仍然保存着这些事实，镜像会根据它重建。

在云端模式下，相关记忆可能会成为发送给提供方的上下文的一部分，条件与任何其他上下文相同。见[本地与云端](local-and-cloud.md)。

在聊天中遗忘，也会从运行时数据库中该聊天的运行历史里删除这些词：轮次记录、检查点、尝试、任务计划、最终答案（包括答案删除会清除的副本）、候选知识、上下文报告、通知、该聊天产生的研究成果，以及引用过它们的置顶消息。其他记录所依赖的记录会保留，但被遗忘的词会被清空，连同存放在旁边的任何摘要；其余记录会被删除。遗忘到来时仍在运行的轮次无法把这些词写回去：它的事件会被清空，等它结束时，它的记录会再次被删除。随后数据库的预写日志会被合并，这样旧副本就不会留在 `-wal` 文件中。其他聊天的记录不受影响。尚未发送的排队消息会被保留，此时遗忘会说明它未能完全生效。如果有哪个表是任何删除步骤都不认识的，回复中会点出它的名称，并说明重试也无法清除它。

比较词语时不区分大小写，用其他文字书写的数字也被视为同一个数字（全角的“１２”就是 12）。被遗忘的数字只在它作为独立数字出现的地方匹配：与它连写在一起的字母和数字中不能含有其他数字，而且它不能跨过 `.`、`,`、`:`、`/`、`-` 或 `_` 接上另一个数字。遗忘“12”会删除“code 12”“12kg”和“B12”，但不会删除“room 312”“3.12”“12.5”“12:30”或“2026-10-12”；遗忘“200”也不会删除“1,200”。在运行历史中，运行时计数或计时得到的单纯数字（例如 `elapsed_ms` 或 `step_count` 的值）不会被匹配。

记忆读取方还会检查一个持久的遗忘权威记录。全新的记忆主目录会在接受写入之前创建它。较旧的语义存储只有在没有记录任何先前删除时才会原地升级；其中保留的记忆仍然可用。如果现有的权威记录无法读取、权威记录缺失但存在已持久化的见证，或者记录了遗忘屏障，读取方就会扣留受影响的记忆。删除权威记录文件并不能恢复已遗忘的内容。

待处理的删除日志会保留其令牌以便恢复。一旦永久的限定范围撤销存在，完成步骤就会清除日志中多余的令牌，同时保留操作标识和状态。撤销权威记录仍然保留。
