# 花费限额与价格保护

没有你控制的明确上限，VOOL 绝不会代你花钱。本页介绍保护付费模型调用和付费资源的各层机制，以及付费调用中途被中断时会发生什么。

## 两种价格，一条规则

* **目录价格** — 提供方当前为某个模型公布的价格。VOOL 会发现它；它只是信息，不是许可。
* **你接受的价格** — 你在设置中为该提供方和模型批准的上限。发现的价格高于你的上限时，会在联系提供方 **之前** 被拒绝。拒绝消息会如实说明这一点：模型没有运行，没有发送任何内容，也没有产生任何费用。

## 支出上限

对于付费调用，VOOL 会在每次调用之前按上限预留资金：

| 上限 | 含义 |
| --- | --- |
| 每次调用 | 单次调用的预计费用上限。 |
| 每个任务 | 一个任务在其所有调用中最多可以花费的金额。 |
| 每日 / 每月 | 整个周期内付费使用的上限。 |

会越过上限的调用在发送之前就会被拒绝。拒绝消息会点出拒绝它的那个上限（`per_task_spend_cap_exceeded` 及其同类），措辞有意采用发送前的说法：*“running it would exceed your spend cap”*——绝不会声称已经联系过提供方。

## 固定的模型绝不会被悄悄替换

如果你明确选择了一个付费模型，而某项保护拒绝了它，VOOL **不会** 悄悄用更便宜的模型来回答。这一轮会失败，并点出你选择的模型、实际起作用的关卡，以及这句话：*“no other model was substituted.”* 请自己选择另一个模型，或有意地提高上限。

## 已付费，但回答始终没有到达

如果一次付费调用已经扣费，但回答没有到达，结果就是 **未知**——VOOL 不会假装它失败了或成功了：

* 不会凭空编造一个回答来代替它，也不会假定已经退款。
* 这笔付款会作为未解决的记录保留下来。
* 设置会把它列在 **Paid calls waiting for an answer** 下，在那里按 **Resume** 会再请求一次同样的回答，而且 **不会再次付费**。

所以在这些情况下，绝不会建议你盲目重试：直接重新发送可能会付两次钱。Resume 是唯一受支持的方式。

## 自动钱包付款（x402）

要求用 Base 或 Base Sepolia 上的 USDC 进行 x402 付款的网站，可以从你的 Crypto Pilot 钱包付款，在这些上限之内只需一次 PIN 批准；目前还没有用这种方式进行过真实的主网付款。设置中模型市场里的按次付费选项从 Solana 主网钱包付款，在这些上限之内每次调用批准一次，尚未在真实的链上测试过。由钱包付款的资源（见[钱包](../guides/wallet.md)）有自己的自动付款上限。要求金额超过上限的资源根本不会被付款；你可以有意地提高上限，或在你批准的情况下，通过明确的提案为该资源付款。
