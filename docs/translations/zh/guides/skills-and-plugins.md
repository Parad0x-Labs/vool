# 技能与插件

**技能** 是为重复性任务打包好的一组指令。**插件** 为运行时添加新的工具。

## 内置与外部安装

VOOL 自带一个 **原生技能库**——随应用本身提供的技能——在当前版本中还自带 **VOOL Database** 插件。你也可以安装自己的技能和插件。

| | 内置（随 VOOL 提供） | 外部安装 |
| --- | --- | --- |
| 所在位置 | 应用内部 | 你的插件文件夹（在设置中指定） |
| 更新 | 随应用更新 | 在你更新该包时 |
| 可以禁用 | 可以——逐个禁用 | 可以——逐个禁用 |
| 授予权限 | **否** | **否** |

两种来源都遵循两条规则：

* **技能只负责教，绝不授权。** 技能声明的工具是一种 *收窄* 信号（该工作流的工具预算），绝不是对任何东西的授权。权限控制器不读取技能。
* **只有一份清单。** 控制台显示的目录和运行时加载的包是同一个列表。技能出现在列表中并不证明它能加载——每个条目都带有其实时状态（可用、已禁用、缺少前提条件、契约无效）及原因。

## 查找技能

“技能与插件”会先列出 VOOL 自己的技能。**浏览** 中有 53 个现成的 VOOL 技能。它们都是纯文本的：每个都是随应用打包的一组指令，因此“浏览”无需联网查询就能列出它们。使用 VOOL 工具的 VOOL 技能列在 **技能宝典** 标签页中，其中 VOOL 团队的技能排在最前面。启用技能之前请先审查它。

## 可用状态

技能可能会显示为不可用，并附带一个归类好的原因：缺少前提条件（例如，数据库技能需要启用数据库插件）、这台电脑上没有可用的能力、契约无效，或被你禁用。原因按条目显示，禁用也是按条目进行的，并且重启后仍然有效。

## 重复的标识

如果两个包声明了相同的插件标识（比如一个内置包和一个已安装的副本），会 **确定性地** 保留内置的那个，被舍弃的副本会在目录中报告——绝不会被悄悄遮蔽。

## 安装你自己的技能

从应用内的目录安装，或让 VOOL 指向你自己的插件文件夹。包中带有一个声明其工具的清单（`plugin.json`）；如果清单中的权限声明与其声明的行为类别不符，它会在加载时被拒绝。

{% hint style="danger" %}
在验证之前，请审查整个包。审查是关于特定字节的证据，而不是安全证书，也不是权限授予。
{% endhint %}

## v0.7 中的包批准

验证涵盖包中的每个文件和目录，包括处理程序可执行文件、内置的库、依赖锁定文件、引用、资源和可执行模式位。添加、删除、重命名或更改其中任何一项都会使批准失效。符号链接、硬链接、特殊文件、特权模式、不稳定的读取以及过大的分发包都会被拒绝。当前的采集上限为 4,096 个条目、每个文件 64 MiB、每个包 128 MiB。包内不存在会被忽略的缓存或状态目录。

此前存储的仅含元数据的批准在此版本中不会激活包。请审查完整的分发包，再次明确地验证它，然后启用它。更新在经过验证并启用之前一直保持禁用；批准绝不会被悄悄迁移。当较旧的回执没有绑定完整的分发包时，受管理的附加组件还需要一次新的、经过认证的商店审查；普通验证无法替代那份回执。

`requires` 指明已安装的插件依赖。验证会固定它们的递归批准摘要；每个依赖都必须已经通过验证并已启用。依赖一旦被更改、更新、禁用或撤销，依赖它的包就会变得不可用，通过缓存的工具也一样。准入时会在计算哈希之后，重新检查整个已采集闭包的启用和撤销状态。重新验证一个依赖并不会为父包悄悄批准其新的字节：请把每个父包也审查并重新验证一遍。每个 `approval_digest` 都绑定其包摘要和依赖批准，所以即使父包自身的文件保持不变，传递依赖的变化也会改变该批准。循环依赖的批准无法激活。依赖闭包最多 64 个包。

每次已注册的调用都会再次检查生命周期状态，并为包及其固定的依赖闭包采集私有的只读副本。工具契约必须与采集到的清单相符。已注册的处理程序从该采集副本启动；采集之后再编辑源文件，也无法替换该处理程序或其打包的文件。执行观测记录包含包摘要、递归批准摘要和依赖摘要。即使本地的底层调用方选择了较弱的覆盖设置，已注册的包也需要真正的内核隔离。无法安全地进行不跟随链接的描述符采集、或无法提供内核隔离的主机，会拒绝已注册的包。调用超时限定在 1–300 秒之间；在删除调用的执行副本之前，会先停止该调用拥有的进程组。

请把持久输出、缓存和日志放在 `PLUGIN_SCRATCH` 中，而不是放在可执行代码旁边。只读工具不会获得写入授权。其他工具可以写入暂存区，但不能修改自己的执行副本。`VOOL_PLUGIN_DEPENDENCIES` 是一个 JSON 映射，从声明的依赖标识映射到采集到的依赖目录。请把其他第三方库及其锁定文件打包在包内；仅有锁定文件并不能证明外部环境。主机解释器和系统库仍然是受信任平台的一部分，而不被当作经过审查的第三方包字节。这项完整性检查不认证行为，不证明从已批准分发包之外下载或加载的任意代码，不代理每一个内部效果，也不替代原生钱包批准。

## 编写技能

技能是一个文件夹，里面有一个指令文件以及它引用的任何文件：

```text
my-skill/
├── SKILL.md
└── templates/
```

在应用内起草（`skill.create` 会暂存它，但不激活任何东西），验证它，然后安装以激活——特意分成三个独立步骤，这样编写技能绝不会隐式地改变行为。目录和编写格式仍在为公开发布做最后的完善。
