# 技能与插件

**技能** 是为重复性任务打包好的一组指令。**插件** 添加工具、模型提供方或附加组件扫描器。插件也可能打包了技能。

## 内置与外部安装

VOOL 自带一个 **原生技能库**——随应用本身提供的技能——在当前版本中还自带 **VOOL Database** 插件。你也可以安装自己的技能和插件。

| | 内置（随 VOOL 提供） | 外部安装 |
| --- | --- | --- |
| 所在位置 | 应用内部 | 你的插件文件夹（在 VOOL 的插件窗口中管理，而不是在设置中） |
| 更新 | 随应用更新 | 在你更新该包时 |
| 可以禁用 | 应用的窗口中还没有按钮 | 可以——在插件窗口中 |
| 授予权限 | **否** | **否** |

两种来源都遵循两条规则：

* **技能只负责教，绝不授权。** 技能声明的工具是一种 *收窄* 信号（该工作流的工具预算），绝不是对任何东西的授权。权限控制器不读取技能。
* **只有一份清单。** 控制台显示的目录和运行时加载的包是同一个列表。技能出现在列表中并不证明它能加载——每个条目都带有其实时状态（可用、已禁用、缺少前提条件、契约无效）及原因。

## 查找技能

“技能与插件”会先列出 VOOL 自己的技能。**浏览** 中有 75 个现成的 VOOL 技能。每个都是随应用打包的一组指令，因此“浏览”无需联网查询就能列出它们。其中 22 个会在被选中的轮次中使用 VOOL 工具（你的邮件、笔记、文件、PDF、钱包等）：技能的工具只会收窄 VOOL 本来就为你的请求提供的范围，关闭的工具保持关闭，每次调用都会像平常一样征求你的同意。它的 **源码与技术细节** 会列出它使用的工具。**技能宝典** 标签页把 VOOL 团队的技能列在最前面。启用技能之前请先审查它。

从“浏览”添加技能的方式取决于它的制作者：

* **VOOL 制作的技能**（上面的 75 个）：按 **添加这个技能**。VOOL 会在你的电脑上检查该文件正是它随附的那一个，并读取它查找有风险的指令，然后把结果显示给你。不需要密钥，也不会向任何地方发送任何内容。如果文件不一致，VOOL 会拒绝它并告诉你。
* **其他制作者的技能**（其他发布者的技能，或你粘贴的 GitHub 链接）：按 **下载并扫描**。VOOL 会按固定版本下载这个公开技能，并在你的电脑上检查它。如果你启用了扫描插件，它也会收到技能的内容，它的报告会添加在 VOOL 自己的报告旁边。阅读结果，然后选择是否添加该技能：如果任何一项检查报告了问题，VOOL 只会在你接受该版本的风险之后才添加它。除非你的扫描插件要求，否则不需要密钥。

你也可以在聊天中制作自己的技能，完全不需要密钥：请参阅[制作你自己的技能](../../../guides/make-your-own-skill.md)。

你也可以在任何聊天中提问：*我有哪些技能？* 会列出它们，*怎样添加技能？* 会说明两种方式。

## 开启或关闭技能

依次打开 **技能与插件**、**我的附加组件**、**技能**。每个技能都显示 **开启** 或 **关闭**，并带有 **启用** 或 **禁用** 按钮。你关闭的技能在你重新开启之前不会在任何聊天中使用。它的文件会被保留。

**插件** 下的 **Built-in skills** 卡片没有自己的按钮：请在 **技能** 下逐个开启或关闭其中的技能。

## 查看哪个技能影响了回答

当技能的指令参与了 VOOL 撰写某个回答时，回答下方会有一行简短的说明，例如 **用到的技能：Browser**。它在聊天打开期间紧跟在回答之后出现；之后从历史记录中加载的回答暂时不会显示它。随大多数回答一起生效的回答风格规则不会在那里列出。

## 用于构建 VOOL 的技能

技能库中还有 VOOL 团队构建 VOOL 时使用的技能：代码审查、测试运行、发布检查、流水线修复等。它们不会在聊天中或“技能”页面上列出，也不会影响日常回答。开发者可以用 `VOOL_DEVELOPER_SKILLS=1` 启动 VOOL 来显示和使用它们。

## 可用状态

技能可能会显示为不可用，并附带一个归类好的原因：缺少前提条件（例如，数据库技能需要启用数据库插件）、这台电脑上没有可用的能力、契约无效，或被你禁用。原因按条目显示，禁用也是按条目进行的，并且重启后仍然有效。

## 重复的标识

如果两个包声明了相同的插件标识（比如一个内置包和一个已安装的副本），会 **确定性地** 保留内置的那个，被舍弃的副本会在目录中报告——绝不会被悄悄遮蔽。

## 安装你自己的技能

从应用内的目录安装，或让 VOOL 指向你自己的插件文件夹。包中带有一个声明其工具的清单（`plugin.json`）；如果清单中的权限声明与其声明的行为类别不符，它会在加载时被拒绝。

{% hint style="danger" %}
在验证之前，请审查整个包。审查是关于特定字节的证据，而不是安全证书，也不是权限授予。
{% endhint %}

## 附加组件中的插件

打开 **附加组件 → 我的附加组件 → 插件**。审查一个本地文件夹，或处于确切提交的公开 GitHub 文件夹。安装会采集完整的包并让它保持禁用。签名的商店插件使用现有的注册表链，同样以禁用状态安装。在启用工具或服务之前，请单独审查访问清单。保存服务密钥不会引发任何请求；连接测试和刷新模型列表都是明确的操作。

禁用会移除工具并停止正在运行的调用。卸载会先禁用，再删除其拥有的文件和暂存区，默认删除已保存的密钥，并保留历史记录。更新和重新安装需要一次新的审查，并以禁用状态开始。来自其他仓库或发布者的更新不会保留已保存的密钥。UsePod 和 Eyebrow 已不再是 VOOL 的一部分，VOOL 也不为二者提供插件。已保存的 UsePod 或 Eyebrow 密钥会留在这台电脑上，VOOL 不会使用它；附加组件会一直提示这一点，直到你关闭该通知。使用过 UsePod 模型的聊天在升级后没有选中的模型，并且在这些聊天中“自动”不会切换到云端模型；会有通知说明这一点，直到你关闭它。

请参阅[插件编写](../../../guides/plugin-authoring.md)和[附加组件检查](addon-security.md)。

## 完整的包批准


验证涵盖包中的每个文件和目录，包括处理程序可执行文件、内置的库、依赖锁定文件、引用、资源和可执行模式位。添加、删除、重命名或更改其中任何一项都会使批准失效。符号链接、硬链接、特殊文件、特权模式、不稳定的读取以及过大的分发包都会被拒绝。当前的采集上限为 4,096 个条目、每个文件 64 MiB、每个包 128 MiB。包内不存在会被忽略的缓存或状态目录。

此前存储的仅含元数据的批准在此版本中不会激活包。请审查完整的分发包，再次明确地验证它，然后启用它。更新在经过验证并启用之前一直保持禁用；批准绝不会被悄悄迁移。当较旧的回执没有绑定完整的分发包时，受管理的附加组件还需要一次新的、经过认证的商店审查；普通验证无法替代那份回执。

`requires` 指明已安装的插件依赖。验证会固定它们的递归批准摘要；每个依赖都必须已经通过验证并已启用。依赖一旦被更改、更新、禁用或撤销，依赖它的包就会变得不可用，通过缓存的工具也一样。准入时会在计算哈希之后，重新检查整个已采集闭包的启用和撤销状态。重新验证一个依赖并不会为父包悄悄批准其新的字节：请把每个父包也审查并重新验证一遍。每个 `approval_digest` 都绑定其包摘要和依赖批准，所以即使父包自身的文件保持不变，传递依赖的变化也会改变该批准。循环依赖的批准无法激活。依赖闭包最多 64 个包。

每次已注册的调用都会再次检查生命周期状态，并为包及其固定的依赖闭包采集私有的只读副本。工具契约必须与采集到的清单相符。已注册的处理程序从该采集副本启动；采集之后再编辑源文件，也无法替换该处理程序或其打包的文件。执行观测记录包含包摘要、递归批准摘要和依赖摘要。即使本地的底层调用方选择了较弱的覆盖设置，已注册的包也需要真正的内核隔离。无法安全地进行不跟随链接的描述符采集、或无法提供内核隔离的主机，会拒绝已注册的包。调用超时限定在 1–300 秒之间；在删除调用的执行副本之前，会先停止该调用拥有的进程组。

请把持久输出、缓存和日志放在 `PLUGIN_SCRATCH` 中，而不是放在可执行代码旁边。只读工具不会获得写入授权。其他工具可以写入暂存区，但不能修改自己的执行副本。`VOOL_PLUGIN_DEPENDENCIES` 是一个 JSON 映射，从声明的依赖标识映射到采集到的依赖目录。请把其他第三方库及其锁定文件打包在包内；仅有锁定文件并不能证明外部环境。运行时解释器和系统库仍然是受信任平台的一部分，而不被当作经过审查的第三方包字节。这项完整性检查不认证行为，不证明从已批准分发包之外下载或加载的任意代码，不代理每一个内部效果，也不替代原生钱包批准。

在 macOS 上，插件代码在 macOS 沙盒中运行。密钥只通过处理程序的私有输入传给它，绝不通过它的环境变量，因为在 Mac 上，同一用户的任何程序（包括插件代码）都能读取另一个程序启动时的环境。需要在环境中获得密钥的连接服务器只在可选的隔离 Linux 运行时中运行，这个运行时由你自己准备；VOOL 绝不会启动虚拟机或下载镜像。没有它时，该插件保持关闭并说明原因。Linux 使用 bwrap，包括私有的进程命名空间和 `/proc`。

在 macOS 上，声明了网络的工具只能连接到 VOOL 为每次调用启动的私有代理，而该代理只连接到声明的主机。在 Linux 上和隔离运行时中，插件进程没有网络。原生的提供方和扫描器请求在所有平台上都使用各自独立的、面向声明主机的 HTTPS 传输。
