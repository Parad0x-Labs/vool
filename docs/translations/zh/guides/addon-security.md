# 附加组件检查

附加组件把浏览、检查和安装分开进行。扫描描述的是特定的字节；它不是安全保证、对发布者的认可、运行时权限或钱包批准。

“浏览”会先列出 VOOL 自己的技能，包括随应用打包的 75 个 VOOL 技能（其中 22 个使用 VOOL 工具，这些工具只会收窄 VOOL 本来就提供的范围），然后是经过审查的目录附加组件。“技能宝典”把 VOOL 团队的技能列在最前面，排在编辑精选和推荐技能之上。

## VOOL 制作的技能：本地检查

VOOL 制作的 75 个技能随应用一起提供，每个都在 VOOL 自己的目录中用 SHA-256 固定，并在 VOOL 发布时经过审查。对于这些技能，**添加这个技能** 只运行 VOOL 的本地检查：不需要密钥，不消耗扫描额度，也不发出网络请求。

1. VOOL 从应用自带的副本中读取技能和许可证，只有当它们的 SHA-256 与固定值一致时才接受，否则拒绝（*这个 VOOL 技能的文件与 VOOL 自带的副本不一致，因此没有添加。*）。
2. VOOL 的本地检查会读取技能，查找有风险的指令，并显示结果。干净的结果可以用 **添加并打开** 添加；任何被标记的内容都需要你针对那个确切版本另行明确同意。**拒绝** 会把它丢弃。
3. 之后的安装遵循与其他技能相同的生命周期：确切的文件被安装、验证并启用。已安装的技能每次加载时都会与其固定的 SHA-256 进行核对；文件一旦被更改，该技能就会变得不可用。

本地检查是对固定字节的静态读取，不保证安全性或回答质量。其他制作者的技能绝不会走这条路径。

## 公开技能

选择一个处于固定修订版本的公开 GitHub 技能，并批准下载其内容。VOOL 会在这台设备上检查它。没有启用扫描插件时，页面会说明检查只在这台设备上进行。这条路径不需要扫描器密钥。

启用了扫描插件时，在请求扫描后，该插件也会收到公开技能的内容。这可能会消耗它的服务额度。本地聊天、私有的工作区文件和其他凭据不会被提交。保存密钥和打开附加组件都不会发出连接测试或扫描请求。请求不会自动重试。

阅读检查结果，并另行接受安装。报告验证要求完整的覆盖范围和有效的检查结果。通过的报告没有任何检查发现或策略违规。另行提供的风险接受会绑定到经过审查的那个版本；它绝不会改变报告，也绝不会授予更多访问权限。过期的审查、被更改的暂存字节、链接以及冲突的目标文件夹都会被拒绝。回执绑定完整的已安装分发包。文件被更改后，运行时就不再可用。技能指导要么被完整插入，要么在放不进提示词预算时被明确省略。

## 可选的扫描器

远程扫描器是可选的。没有启用扫描插件时，由 VOOL 在这台设备上的检查来决定技能能否安装；早期版本则要求进行远程扫描。

要添加一个扫描器，请通过“插件”部分安装其制作者提供的扫描插件，保存你自己的密钥，审查访问权限，然后启用它。它的声明会给出一个用于明确连接测试的路径和一个用于请求扫描的路径，由共享的原生插件传输层发出这些请求。VOOL 没有内置的扫描器客户端，也没有集中的扫描器密钥设置，并且不提供自己的扫描插件。旧版 VOOL 中保存的 Eyebrow 密钥会留在这台电脑上，不会被使用。标识 `vool-plugin-eyebrow` 和 `vool-plugin-usepod` 已被保留；声称使用其中之一的其他包会在审查前被拒绝。

VOOL 在这台设备上的检查总会运行。扫描插件的报告会添加在它旁边：任何一方发现问题都会阻止安装，而且插件的报告必须指明它检查的确切内容。扫描插件绝不能单独批准一次安装。

已启用的扫描器缺少密钥或密钥被拒绝时，会明确地失败。VOOL 绝不会悄悄地用一个通过的本地结果来代替那次被请求的远程扫描。超时、服务错误、重定向、过大的响应和不完整的报告都会让安装保持未被接受的状态。超时的请求可能仍然消耗了服务额度。

## 可执行包与商店审查

插件使用完整的本地文件夹包审查或固定的公开 GitHub 包审查，与纯文本技能导入器分开。安装不运行任何包代码，并让它保持禁用。商店插件还需要现有的签名回执和完整分发包摘要。启用需要一份单独的访问清单，涵盖工具、效果、确切的主机、凭据槽位和打包的服务器。

可执行代码在调用时只收到它自己声明的密钥。它无法读取其他插件的槽位、所有者的付费模型密钥，也无法获得钱包的签名、限额、批准或回执权限。它的输出仍然不受信任。字节一旦改变，同意就会被撤回；禁用会停止调用。不支持的隔离方式会拒绝执行。运行时限制请参阅[插件编写](../../../guides/plugin-authoring.md)。

如果 VOOL 无法读取它的插件记录，没有记录的包会停止提供技能（随 VOOL 提供的除外），损坏的文件会保留在新文件旁边。如果无法读取你的开启和关闭选择，在你重新开启某个插件之前，所有插件都视为关闭。

## 本地 API 与传输

`GET /api/addons` 读取清单。`POST /api/addons` 上的变更操作需要所有者本地访问、JSON、同源浏览器请求以及特定于操作的字段。插件开关和生命周期入口（`POST /api/plugins/enable`、`POST /api/plugins/lifecycle`）适用同样的 JSON 和同源规则。公开源的下载使用确切的修订版本和有大小上限的已验证数据块。原生服务要求声明的公开 HTTPS 主机，验证 TLS，固定解析出的公开地址，拒绝重定向，限制响应大小，并在插件被禁用时停止。

本地的模拟 HTTPS 服务可以在不进行付费调用的情况下验证传输和错误处理。它们不能证明实际服务的可靠性、计费、模型能力，也不能证明在其他应用程序中的安装。这些需要单独验证。
