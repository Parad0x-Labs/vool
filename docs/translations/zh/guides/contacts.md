# 联系人

联系人列表是一个本地的结构化通讯录（人、他们的端点和付款别名），VOOL 可以用它来代替让你重新输入地址。由于通讯录会用于付款和消息，对它的编辑是 **受保护的**：要经过审查、确认，并被记录下来。

## 受保护的编辑

更改已保存的联系人是一个两步流程：

1. **审查** — 准备并显示更改。如果自你打开以来该条目已被更改（在另一个窗口或另一台设备上），更改会被拒绝，并显示 *“changed after this was reviewed; review it again. Nothing changed.”*
2. **确认** — 只有在审查界面中输入你的 PIN 或密码，更改才会被提交。

每次拒绝都会明确说明 **没有保存或更改任何内容**——因为确实没有。如果你的 PIN 已被接受，但保存本身失败了，消息会如实说明：PIN 已接受，请在确认过期之前重新保存。

## 保护措施

* 每个联系人同一时间只能有一项更改；待处理的更改数量有上限。
* 删除联系人不会悄悄改写历史：对已删除联系人的引用会报告为 *“That contact was deleted”*——绝不会被悄悄重新解析为别人。
* 导入绝不会只应用一部分：如果无法读取来源，就什么都不会导入。

## 为什么这样设计

输错一个付款地址，钱就再也找不回来了。审查这一步的存在，是为了让任何模型轮次、任何批量编辑、任何过时的窗口，都无法在没有人确认最终确切条目的情况下，改变“Alice”所指的人。
