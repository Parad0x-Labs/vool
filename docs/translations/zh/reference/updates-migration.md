# 更新与迁移

## 更新如何进行

从 0.7.5 起，VOOL 会自行更新：打开“自行联网”后，它会显示通知，只需按一下即可安装新版本。在 Mac 上从 0.7.4 或 0.7.3 更新：打开“自行联网”（设置 > 隐私与权限），然后按一次“检查更新”。在 Linux 上从 0.7.4 或更早版本，或在 Mac 上从 0.7.2 及更早版本更新：下载 0.7.7，直接覆盖安装到当前版本上。你的聊天记录和设置保存在应用之外的用户资料目录中。

打开“自行联网”时，VOOL 会在启动时以及每天一次检查新版本，无需按“检查”就会显示通知。关闭时，VOOL 不会获取任何内容，标题栏会显示 **更新检查已关闭**。

已签名的更新包会运行一条经过验证、可自动回滚的流程：

1. **下载** — 对照已签名的清单进行验证。
2. **分阶段安装** — 新版本安装在旧版本旁边。
3. **迁移** — 你的数据被迁移到新的存储版本。如果迁移失败，你的数据会恢复到之前的版本，应用会在旧版本上重启：*“Your data was restored to the previous version.”*
4. **健康检查** — 新版本必须证明自己能够提供服务，旧版本才会退役。
5. **切换** — 原子操作；之前的版本会保留，作为回滚目标。

在 Linux 上，tar 包安装也以同样的方式更新。新版本会安装在正在运行的版本旁边，`current` 一步切换过去。如果新版本运行不正常，VOOL 会自行切换回之前的版本。手动 **Roll back** 在 Mac 和源码安装上提供，但 Linux tar 包安装尚未提供。

如果任何一个阶段失败，应用会保持原样——失败消息会点出该阶段（`verification_failed`、`insufficient_disk_space`、…），而且每个阶段都有自己的恢复说明。

## 数据兼容性

* 你的用户资料目录、聊天、回执和设置都位于应用包之外，所以替换应用绝不会替换你的数据。
* 本地存储拒绝在 **降级** 时打开：由较新 VOOL 写入的数据库不会被较旧的版本悄悄读取——它会说明情况并拒绝，因为猜测未知的存储布局会损坏数据。要读取新数据，请重新安装较新的版本。
* 更新安装的文件和更新状态本身都会连同回执记录在你的用户资料目录下，因此“哪个版本动过我的数据”这个问题事后也能回答。

## 测试版渠道

当前的发布线是 **测试版**（见[发布状态](../trust/release-status.md)）。更新由固定的发布者密钥签名，并在安装之前进行检查。macOS 应用本身是 ad-hoc 签名的，未经公证，所以 macOS 可能会在新版本首次启动时请你确认。
