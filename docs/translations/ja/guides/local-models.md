# ローカルモデルを実行する

## ランタイムをインストールする

VOOLはローカルのモデルサーバーとやり取りします。macOSアプリには専用のローカルモデル実行環境が含まれているため、Macではこの手順を省略できます。Linuxとソースからのインストールでは、Ollamaなどのサーバーをインストールして起動し、モデルをダウンロード（pull）します。

```bash
ollama serve
ollama pull qwen2.5-coder:7b
```

## VOOLにランタイムを指定する

**設定 → モデルとプロバイダ** を開きます。動作中のローカルランタイムは自動で検出されます。モデルを選ぶと、モード表示が「ローカル」に変わります。

## 一度だけ認定する

ローカルモデルが回答を書くのは、認定を受けた後だけです。**設定 → モデルとプロバイダ → ローカルモデル** を開き、モデルを登録してから **Certify** を選びます。認定では、お使いのマシンで短いツールチェックが実行されます。何もダウンロードされず、どこにも接続しません。モデルが合格するまで、VOOLはそのモデルに最終的な回答を書かせません。

## サイズの目安

| モデルのサイズ | 必要なメモリ | 向いている用途 |
| --- | ---: | --- |
| 3B | 約4 GB | 短い編集、ちょっとした質問 |
| 7–8B | 約8 GB | 一般的な用途、ほとんどのコーディング |
| 14B | 約16 GB | より長い推論 |
| 32B+ | 32 GB以上 | 重い作業、遅め |

{% hint style="info" %}
量子化したビルドを使うと、メモリの使用量を大幅に減らせます。4ビットの7Bモデルなら、約5 GBで快適に動作します。
{% endhint %}

## 遅いとき

* より小さいモデルか、より強く量子化されたモデルを選びます。
* メモリを多く使うほかのアプリケーションを閉じます。
* コンテキストを短くします。リクエストに含めるファイルが少ないほど、処理する量も少なくなります。
