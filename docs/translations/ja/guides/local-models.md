# ローカルモデルを実行する

## ランタイムをインストールする

VOOLは標準でOllamaを使ってローカルモデルを実行します。OpenAI互換のエンドポイントを持つほかのローカルランタイムも使えます。Ollamaは別のプログラムで、[ollama.com](https://ollama.com)から単独でインストールします。macOSアプリには専用のローカルモデル実行環境が含まれているため、Macではこの手順を省略できます。Linuxとソースからのインストールでは、Ollamaをインストールして起動し、モデルをダウンロード（pull）します。

```bash
ollama serve
ollama pull qwen3:4b
```

標準では、VOOLがローカルモデルを選びます。お使いのコンピュータに合ったサイズのQwenのモデルです。多くのコンピュータではそのモデルは `qwen3:4b` で、メモリが32 GB以上のコンピュータでは、より大きなQwenのモデルが標準になります。

## VOOLにランタイムを指定する

**設定 → モデルとプロバイダ** を開きます。動作中のローカルランタイムは自動で検出されます。モデルを選ぶと、モード表示が「ローカル」に変わります。

## 一度だけ準備する

ローカルモデルが回答を書くのは、VOOLがそのモデルを確認した後だけです。**設定 → モデルとプロバイダ → ローカルモデル** を開き、モデルの横にある **このモデルを使う** を押します。VOOLはお使いのコンピュータ上で、そのモデルがVOOLのツールを十分に使いこなして回答できるかを静かに確認します。確認には一、二分かかることがあります。何もダウンロードされず、どこにも接続しません。合格すると、モデルに **準備完了** と表示され、VOOLはそのモデルで回答します。それまでは、VOOLはそのモデルに最終的な回答を書かせません。

* **向いていません：** モデルがVOOLのツールを十分に使いこなせません。VOOLが代わりにできることを示します。このコンピュータ向けにVOOLが選んだモデルを使うかダウンロードするか、クラウドモデルを使います。
* **確認が終わりませんでした：** Ollamaが開いていることを確認してから、**もう一度試す** を押してください。遅いコンピュータでは、もう一度試す必要があることがあります。

VOOLの起動時に準備完了のローカルモデルがない場合、VOOLはこのコンピュータにあるモデルのうち最大三つを、選んだモデルから順に確認し、最初に合格したモデルを使います。このコンピュータには大きすぎるモデルは飛ばします。準備完了のモデルは、準備ができていないモデルより常に先になります。

## サイズの目安

| モデルのサイズ | 必要なメモリ | 向いている用途 |
| --- | ---: | --- |
| 3B | 約4 GB | 短い編集、ちょっとした質問 |
| 7–8B | 約8 GB | 一般的な用途、ほとんどのコーディング |
| 14B | 約16 GB | より長い推論 |
| 32B+ | 32 GB以上 | 重い作業、遅め |

{% hint style="info" %}
量子化したビルドを使うと、メモリの使用量を大幅に減らせます。4ビットの7Bモデルなら、約5 GBで快適に動作します。
{% endhint %}

## 遅いとき

* より小さいモデルか、より強く量子化されたモデルを選びます。
* メモリを多く使うほかのアプリケーションを閉じます。
* コンテキストを短くします。リクエストに含めるファイルが少ないほど、処理する量も少なくなります。
