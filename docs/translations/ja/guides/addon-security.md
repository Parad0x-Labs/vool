# スキルの発見とEyebrowのチェック

「スキルとプラグイン」のページには四つのタブがあります：**見る**、**スキルコーデックス**、**マイアドオン**、**セキュリティ**。「見る」には、まずVOOL自身のスキルが表示され、そこにはアプリに同梱されたテキストのみのVOOLスキル53個も含まれます。次にレビュー済みのカタログのアドオンが表示され、公開されているGitHubリポジトリを固定したリビジョンで調べることもできます。「スキルコーデックス」には、VOOLチームのスキルが最初に、編集部のおすすめや注目のスキルより上に表示されます。検索では、大文字と小文字や一般的な区切り文字は区別されません。カテゴリと並べ替えの操作で一覧を絞り込めます。ソース、ライセンス、リビジョン、必要条件は、ダウンロードする前に確認できます。

## 初めて使うとき

1. 「セキュリティ」タブでEyebrowのAPIキーを保存します。このタブは 設定 → APIキー からも使えます。キーは既存の認証情報ストアが管理します。保存しても、接続のテストやスキャンは行われません。「接続をテスト」を押したときに、明示的にEyebrowに接続します。
2. 「見る」でスキルを選び、その公開コンテンツのダウンロードと、そのコンテンツをEyebrowに送ることを承認します。これにより、プランに応じてサービスのスキャンの利用枠が消費されます。自動の再試行は行われません。
3. 返ってきたレポートを読みます。HTTPレスポンスが成功しただけでは、問題がないという結果にはなりません。この最初のカタログでは、`pass` の完全なレポートで、検出事項もポリシー違反もない場合にだけ、インストールが許可されます。「拒否」を押すと、ステージされたダウンロードはインストールされずに破棄されます。
4. インストールは別に承認します。VOOLはライセンスを保持し、既存のプラグインのライフサイクルを通じてインストールし、レビューされたパッケージそのものを検証してから、スキルを有効にします。スキルが提案するかもしれないすべての操作には、引き続き既存の権限が適用されます。

スキャンは特定のバイト列に対するベンダーの評価であり、安全性、互換性、回答の品質を保証するものではありません。カタログに含まれていることは、公開者の認定ではありません。

## 境界

コンテンツは、40文字の固定のリビジョンの公開GitHubリポジトリからだけ取得され、スキルとライセンスのファイルはSHA-256で固定されます。このバージョンには、非公開のリポジトリ、アーカイブの展開、インストールスクリプト、実行可能ファイルやMCPのプラグインのインポーターはありません。Eyebrowに送られるのは単体のSKILL.mdだけです。ローカルのチャット、ワークスペースのファイル、認証情報、ライセンスの内容は、スキャンのために送信されません。

ダウンロードしたものは、レビューと承認が済むまで何も動作しません。ローカルで認証されたレシートが、レポートを固定されたコンテンツに結び付けます。インストールでは、期限切れのレビュー（24時間）、変更されたステージ済みのファイル、既存のインストール先ディレクトリが拒否されます。ランタイムは、管理されたスキルをモデルのコンテキストに追加する前に、ライフサイクルの状態とレビュー済みのバイト列を確認します。ファイルの追加、シンボリックリンク、内容の変更があると、そのスキルは利用できなくなります。ガイダンスは丸ごと挿入されるか、プロンプトの予算が足りないために省略されたと明示的に記録されます。スキャンされた指示が黙って切り詰められることはありません。

これらのチェックは、オペレーティングシステムのユーザーとしてすでに実行されている悪意のあるコードを隔離するものではありません。手動でインストールされた既存のプラグインにも及びません。スキャンのレシートによって、新しい実行権限やウォレットの権限が与えられることはありません。

## APIと失敗時の扱い

`GET /api/addons` は、接続のテストやスキャンを行わずに、カタログとローカルの状態を返します。`POST /api/addons` は `save_key`、`remove_key`、`test_key`、`scan`、`install`、`reject` に対応しています。変更を伴う操作には、ループバック、JSON、同一オリジンのブラウザリクエストが必要で、操作ごとに決められたフィールドだけが受け付けられます。呼び出し元が指定したソースのURLやパスは拒否されます。

クライアントは、Eyebrow v1のインラインのスキルソースのリクエストを `/v1/scan` で使います。ベアラー認証、固定のHTTPSオリジン、リダイレクトなし、上限のあるレスポンスサイズ、自動の再試行なしです。明示的な接続のテストには `/v1/version` が使われます。APIリファレンス：https://eyebrow.cc/api/reference

よくある、種類の決まった失敗は次のとおりです。

| コード | 意味 / 対処 |
| --- | --- |
| `eyebrow_key_missing` / `eyebrow_unauthorized` | キーを保存するか、置き換えてください。 |
| `eyebrow_quota` | 再試行する前に、サービスの利用枠を確認してください。 |
| `eyebrow_timeout` / `eyebrow_unreachable` | 自動の再試行はありません。タイムアウトしたスキャンでも、利用枠が消費されることがあります。 |
| `eyebrow_invalid_report` / `eyebrow_no_coverage` | 根拠が不完全です。何も有効になりません。 |
| `addon_source_changed` / `addon_changed` | 固定されたバイト列、またはレビュー済みのバイト列が異なります。有効にしないでください。 |
| `review_untrusted` / `review_expired` | インストールの前に、新しいレビューを取得してください。 |
| `addon_already_installed` | 既存のファイルは保持されました。自動での置き換えは実装されていません。 |

## 現在の制限と検証

変更された既存のパックに対する、自動のアップデート、任意のカタログのインポーター、その場での修復や再インストールの手順はありません。アプリの再起動後に保留中のレビューを復元する機能は、UIには公開されていません。新しいインターフェイスの文字列は、現在は英語で表示されます。翻訳が完全であるとは主張していません。

自動テストでは、公開されているダウンロードとEyebrowの応答を明示的にモックした上で、実際のライフサイクル、スキルの読み込み、APIハンドラ、配信されるブラウザUIを動かして確認しています。これらのテストが証明するのはランタイムとインターフェイスの動作であり、Eyebrowが実際に利用できることや、モデルの能力ではありません。キーを使った実際のスキャンと、パッケージ化されたネイティブアプリの受け入れ確認は、リリース時のチェックとして残っています。これらのテストを実行するのに、キーや有料サービスの呼び出しは必要ありません。
