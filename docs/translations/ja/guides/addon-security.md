# アドオンのチェック

アドオンでは、閲覧、検査、インストールが分かれています。スキャンは特定のバイト列について述べるものであり、安全の保証でも、公開者の推薦でも、実行時の権限でも、ウォレットの承認でもありません。

「見る」には、まずVOOL自身のスキルが表示され、そこにはアプリに同梱されたVOOLのスキル75個も含まれます（そのうち22個はVOOLのツールを使いますが、それらのツールはVOOLがすでに提供しているものを絞り込むだけです）。次にレビュー済みのカタログのアドオンが表示されます。「スキルコーデックス」には、VOOLチームのスキルが最初に、編集部のおすすめや注目のスキルより上に表示されます。

## VOOLが作ったスキル：ローカルのチェック

VOOLが作った75個のスキルはアプリの中に同梱されており、それぞれがVOOL自身のディレクトリでSHA-256によって固定され、VOOLのリリース時にレビューされています。これらのスキルでは、**このスキルを追加** はVOOLのローカルのチェックだけを実行します。キーも、スキャンの利用枠も、ネットワークのリクエストも必要ありません。

1. VOOLは、アプリ自身のコピーからスキルとライセンスを読み込み、それらのSHA-256が固定値と一致しない限り拒否します（*This VOOL skill's file doesn't match the copy that came with VOOL, so it was not added.*）。
2. VOOLのローカルのチェックは、スキルを読んで危険な指示がないかを調べ、結果を表示します。問題のない結果は **追加してオンにする** で追加できます。チェックが指摘したものは、そのバージョンそのものについて、ご自身が別に明示的に了承する必要があります。**拒否** を押すと破棄されます。
3. その後のインストールは、ほかのスキルと同じライフサイクルに従います。そのファイルそのものがインストールされ、検証され、有効になります。インストールされたスキルは、読み込まれるたびに固定されたSHA-256と照合されます。ファイルが変更されていると、そのスキルは利用できなくなります。

ローカルのチェックは固定されたバイト列を静的に読むものであり、安全性や回答の品質を保証するものではありません。ほかの作成者のスキルがこの経路を通ることは決してありません。

## 公開されているスキル

固定したリビジョンの公開GitHubスキルを選び、その内容のダウンロードを承認します。VOOLは `core/local_scan.py` を使って、このデバイス上でそれをチェックします。有効なスキャナープラグインがない場合、ページには、チェックがこのデバイスの中だけで行われたことが説明されます。この経路では、スキャナーのキーは必要ありません。

有効なスキャナープラグインがある場合、スキャンを要求したときに、そのプラグインも公開スキルの内容を受け取ります。これにより、そのサービスの利用枠が消費されることがあります。ローカルのチャット、非公開のワークスペースのファイル、その他の認証情報は送信されません。キーを保存しても、アドオンを開いても、接続のテストやスキャンのリクエストは行われません。リクエストの自動の再試行はありません。

検出事項を読み、インストールは別に承認します。レポートの検証には、完全な対象範囲と有効な検出事項が必要です。合格のレポートには、検出事項もポリシー違反もありません。別に提示されるリスクの受け入れは、レビューされたバージョンに結び付きます。それによってレポートが変わったり、より多くのアクセスが与えられたりすることは決してありません。期限切れのレビュー、変更されたステージングのバイト列、リンク、競合するインストール先フォルダは拒否されます。レシートは、インストールされた配布物全体を拘束します。ファイルが変更されると、実行時に利用できなくなります。スキルのガイダンスは丸ごと挿入されるか、プロンプトの予算に収まらない場合は明示的に省略されます。

## 任意のスキャナー

リモートのスキャナーは任意です。スキャナープラグインが有効になっていない場合、スキルをインストールできるかどうかは、このデバイス上でのVOOL自身のチェックが決めます。以前のバージョンでは、その代わりにリモートのスキャンが必要でした。

追加するには、作成者が提供するスキャナープラグインを「プラグイン」セクションからインストールし、ご自身のキーを保存し、アクセスを確認してから有効にします。その宣言には、明示的な接続のテスト用のパスと、要求されたスキャン用のパスが記されており、共通のネイティブのプラグインの通信路がそれらのリクエストを行います。VOOLには、組み込みのスキャナーのクライアントも、中央でスキャナーのキーを設定する場所もなく、VOOL独自のスキャナープラグインも提供していません。以前のVOOLで保存したEyebrowのキーはこのコンピュータに残りますが、使われません。ID `vool-plugin-eyebrow` と `vool-plugin-usepod` は予約されています。そのどちらかを名乗る別のパッケージは、レビューの前に拒否されます。

このデバイス上でのVOOL自身のチェックは常に実行されます。スキャナープラグインのレポートはその横に追加されます。どちらか一方が問題を見つければインストールは止められ、プラグインのレポートはチェックした内容そのものを示す必要があります。スキャナープラグインが単独でインストールを承認することは決してできません。

有効なスキャナーのキーがないか拒否された場合は、はっきりと失敗します。VOOLが、その要求されたリモートのスキャンを、合格のローカルの結果で黙って置き換えることは決してありません。タイムアウト、サービスのエラー、リダイレクト、サイズが大きすぎるレスポンス、不完全なレポートの場合、インストールは受け入れられないままです。タイムアウトしたリクエストでも、サービスの利用枠が消費されていることがあります。

## 実行可能なパッケージとストアのレビュー

プラグインは、テキストのみのスキルのインポーターとは別に、ローカルフォルダまたは固定された公開GitHubのパッケージの完全なレビューを使います。インストールではパッケージのコードは実行されず、無効のままにされます。ストアのプラグインには、既存の署名付きレシートと配布物全体のダイジェストも必要です。有効にするには、ツール、効果、正確なホスト、認証情報のスロット、同梱のサーバーを網羅した、別のアクセスシートが必要です。

実行可能なコードは、呼び出し時に、自身が宣言したキーだけを受け取ります。ほかのプラグインのスロット、所有者の有料モデルのキー、ウォレットの署名、上限、承認、レシートの権限は読めません。その出力は信頼されないままです。バイト列が変わると同意は取り消され、無効にすると呼び出しが止まります。対応していない隔離では、実行が拒否されます。実行時の制限については、[プラグインの作成](../../../guides/plugin-authoring.md)を参照してください。

VOOLがプラグインの記録を読めない場合、記録のないパックは、VOOLに同梱されているものを除いてスキルの提供をやめ、壊れたファイルは新しいファイルの横に保管されます。オンとオフの選択を読めない場合は、もう一度オンにするまで、すべてのプラグインがオフとして扱われます。

## ローカルAPIと通信

`GET /api/addons` はインベントリを読み取ります。`POST /api/addons` での変更を伴う操作には、所有者のローカルのアクセス、JSON、同一オリジンのブラウザリクエスト、操作ごとに決められたフィールドが必要です。プラグインのオンとオフ、およびライフサイクルの窓口（`POST /api/plugins/enable`、`POST /api/plugins/lifecycle`）にも、同じJSONと同一オリジンのルールが適用されます。公開ソースのダウンロードは、正確なリビジョンと、上限のある検証済みのblobを使います。ネイティブのサービスは、宣言された公開HTTPSホストを必須とし、TLSを検証し、解決された公開アドレスを固定し、リダイレクトを拒否し、レスポンスに上限を設け、プラグインが無効になると停止します。

ローカルの偽のHTTPSサービスで、有料の呼び出しなしに通信とエラー処理を確認できます。それらは、実際のサービスの信頼性、課金、モデルの能力、ほかのアプリケーション内でのインストールを立証するものではありません。それらには別の確認が必要です。
