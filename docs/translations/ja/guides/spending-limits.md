# 支出の上限と価格ガード

VOOLは、あなたが管理する明示的な上限なしに、あなたに代わってお金を使うことは決してありません。このページでは、有料のモデル呼び出しと有料のリソースを守る仕組みの層と、有料の呼び出しが途中で中断されたときに何が起きるかを説明します。

## 二つの価格、一つのルール

* **カタログ価格** — プロバイダがそのモデルについて現在公表している価格です。VOOLはそれを調べますが、それは情報であって、許可ではありません。
* **あなたが承認した価格** — そのプロバイダとモデルについて、あなたが設定で承認した上限です。調べた価格があなたの上限を超えている場合、プロバイダに接続する **前に** 拒否されます。拒否のメッセージは、まさにそのことを伝えます。モデルは実行されず、何も送信されず、何も請求されていません。

## 支出上限

有料の呼び出しでは、VOOLは毎回の呼び出しの前に、上限に照らして金額を確保します。

| 上限 | 意味 |
| --- | --- |
| 呼び出しごと | 一回の呼び出しの、見込みコストの上限。 |
| タスクごと | 一つのタスクが、その呼び出し全体で使える最大額。 |
| 日ごと / 月ごと | 有料利用の、期間全体での上限。 |

上限を超えることになる呼び出しは、送信する前に拒否されます。拒否のメッセージには、拒否した上限の名前（`per_task_spend_cap_exceeded` とその仲間）が示され、その文言は意図的に送信前のものになっています：*「running it would exceed your spend cap」*。プロバイダに接続したと主張することは決してありません。

## ピン留めしたモデルが黙って置き換えられることはない

有料のモデルを明示的に選び、ガードがそれを拒否した場合、VOOLがより安いモデルで黙って答えることは **ありません**。そのターンは、選んだモデルの名前と、実際に止めたゲートの名前を示し、*「no other model was substituted.」* という文とともに失敗します。ご自身で別のモデルを選ぶか、意図して上限を引き上げてください。

## 支払ったのに回答が届かない場合

有料の呼び出しで料金が請求されたのに回答が届かなかった場合、結果は **不明** です。VOOLは、それが失敗したとも成功したとも装いません。

* その代わりに回答がでっち上げられることはなく、返金されたと見なされることもありません。
* 支払いは、未解決として記録に残ります。
* 設定では **Paid calls waiting for an answer** の下に表示され、そこで **Resume** を押すと、同じ回答を一度だけ、**もう一度支払うことなく** 求めます。

だからこそ、このような場合にやみくもに再試行することは決して勧めません。単純に送り直すと、二回支払うことになりかねません。サポートされている方法は、Resumeだけです。

## ウォレットからの自動支払い（x402）

Base上またはBase Sepolia上のUSDCでx402による支払いを求めるウェブサイトには、Crypto Pilotウォレットから支払えます。これらの上限の範囲内で、PINによる一回の承認です。この方法では、メインネットでの実際の支払いはまだ一度も行われていません。設定のモデルマーケットプレイスにある、呼び出しごとに支払うオプションは、Solanaメインネットのウォレットから支払い、これらの上限の範囲内で呼び出しごとに一回承認します。まだ実際のチェーンではテストされていません。ウォレットで支払うリソース（[ウォレット](../guides/wallet.md)を参照）には、専用の自動支払いの上限があります。上限を超える額を求めるリソースには、単に支払われません。上限を意図して引き上げるか、あなたの承認のもとで明示的な提案によってそのリソースに支払うことができます。
