# スキルとプラグイン

**スキル** は、繰り返し行う作業のための指示をまとめたものです。**プラグイン** は、ランタイムに新しいツールを追加します。

## 同梱と外部インストール

VOOLには、**ネイティブのスキルライブラリ**（アプリ本体に付属するスキル）と、現在のビルドでは **VOOL Database** プラグインが同梱されています。ご自身でスキルやプラグインをインストールすることもできます。

| | 同梱（VOOLに付属） | 外部インストール |
| --- | --- | --- |
| 保存場所 | アプリの中 | ご自身のプラグインフォルダ（設定で指定） |
| 更新 | アプリと一緒に | パックを更新したとき |
| 無効にできるか | はい（個別に） | はい（個別に） |
| 権限を付与するか | **いいえ** | **いいえ** |

どちらの入手元にも、次の二つのルールが当てはまります。

* **スキルは教えるだけで、決して権限を与えません。** スキルが宣言するツールは *絞り込み* のシグナル（そのワークフローのツール予算）であり、何かを許可するものでは決してありません。権限コントローラーはスキルを読みません。
* **インベントリは一つ。** コンソールに表示されるカタログと、ランタイムが読み込むパックは同じリストです。リストに表示されていても、読み込めるとは限りません。各項目は現在の状態（利用可能、無効、前提条件の不足、コントラクトが無効）とその理由を持っています。

## スキルを探す

「スキルとプラグイン」には、VOOL自身のスキルが最初に表示されます。**見る** には、すぐに使えるVOOLのスキルが53個あります。これらはテキストのみのスキルです。それぞれがアプリに同梱された指示のまとまりなので、「見る」はオンラインで調べずに一覧を表示します。VOOLのツールを使うVOOLのスキルは **スキルコーデックス** タブに表示され、そこではVOOLチームのスキルが最初に並びます。スキルは、有効にする前にレビューしてください。

## 利用可能かどうかの状態

スキルは、種類の決まった理由とともに、利用不可と表示されることがあります。前提条件の不足（たとえば、データベースのスキルにはデータベースのプラグインが有効になっている必要があります）、このマシンで利用できない機能、無効なコントラクト、またはご自身で無効にした場合です。理由は項目ごとに表示されます。無効化は項目ごとに行われ、再起動後も維持されます。

## 重複する識別子

二つのパックが同じプラグインの識別子を宣言している場合（たとえば同梱のパックとインストールしたコピー）、同梱のものが **決定論的に** 残され、外されたコピーはカタログで報告されます。黙って隠されることは決してありません。

## 独自のスキルをインストールする

アプリ内のカタログからインストールするか、ご自身のプラグインフォルダをVOOLに指定します。パックには、そのツールを宣言するマニフェスト（`plugin.json`）が含まれています。権限の宣言が、宣言された動作クラスと一致しないマニフェストは、読み込み時に拒否されます。

{% hint style="danger" %}
検証の前に、パッケージ全体をレビューしてください。レビューは特定のバイト列についての根拠であり、安全の証明書でも、権限の付与でもありません。
{% endhint %}

## v0.7でのパッケージの承認

検証は、ハンドラの実行ファイル、同梱されたライブラリ、依存関係のロック、参照、アセット、実行可能モードのビットを含め、パッケージのすべてのファイルとディレクトリを対象にします。これらのいずれかを追加、削除、名前変更、変更すると、承認は無効になります。シンボリックリンク、ハードリンク、特殊ファイル、特権モード、不安定な読み取り、サイズが大きすぎる配布物は拒否されます。現在の取り込みの上限は、4,096項目、ファイルあたり64 MiB、パッケージあたり128 MiBです。パッケージの中に、無視されるキャッシュや状態のディレクトリはありません。

以前に保存された、メタデータだけの承認では、このバージョンのパッケージは有効になりません。配布物全体をレビューし、改めて明示的に検証してから、有効にしてください。アップデートは、検証して有効にするまで無効のままです。承認が黙って移行されることは決してありません。管理されたアドオンでは、古いレシートが配布物全体を拘束していない場合、認証された新しいストアのレビューも必要です。通常の検証では、そのレシートの代わりにはなりません。

`requires` は、インストール済みのプラグインの依存関係を指定します。検証では、それらの再帰的な承認ダイジェストを固定します。各依存関係は、すでに検証されて有効になっている必要があります。依存関係が変更、更新、無効化、取り消しされると、それに依存するものは、キャッシュされたツールを通じた場合も含めて利用できなくなります。受け入れの際には、ハッシュの計算の後で、取り込んだ閉包全体について有効の状態と取り消しの状態を再確認します。依存関係を再検証しても、その新しいバイト列が親に対して黙って承認されることはありません。すべての親もレビューして再検証してください。各 `approval_digest` は、そのパッケージのダイジェストと依存関係の承認を拘束するため、推移的な依存関係が変わると、親自身のファイルが同一のままでも、その承認が変わります。循環する依存関係の承認は有効になりません。依存関係の閉包は64パッケージまでに制限されています。

登録された各呼び出しは、ライフサイクルの状態をもう一度確認し、パッケージとその固定された依存関係の閉包を、読み取り専用の非公開コピーとして取り込みます。ツールのコントラクトは、取り込んだマニフェストと一致する必要があります。登録されたハンドラは、その取り込んだコピーから起動するため、取り込みの後にソースを編集しても、そのハンドラや同梱のファイルを置き換えることはできません。実行の観測記録には、パッケージ、再帰的な承認、依存関係のダイジェストが含まれます。登録されたパッケージには、ローカルの低レベルの呼び出し元がより弱い上書き設定を選んだ場合でも、実際のカーネルによる隔離が必要です。リンクをたどらない安全な記述子の取り込み、またはカーネルによる隔離ができないホストは、登録されたパッケージを拒否します。呼び出しのタイムアウトは1〜300秒の範囲に制限されます。呼び出しが所有するプロセスグループは、実行用のコピーが削除される前に停止されます。

永続的な出力、キャッシュ、ログは、実行可能なコードの隣ではなく `PLUGIN_SCRATCH` に保存してください。読み取り専用のツールには、書き込みの許可は与えられません。その他のツールはスクラッチに書き込めますが、自分の実行用のコピーは変更できません。`VOOL_PLUGIN_DEPENDENCIES` は、宣言された依存関係の識別子から、取り込まれた依存関係のディレクトリへのJSONのマッピングです。その他のサードパーティのライブラリとそのロックは、パッケージの中に同梱してください。ロックファイルだけでは、外部の環境を証明できません。ホストのインタプリタとシステムライブラリは、レビュー済みのサードパーティのパッケージのバイト列として表されるのではなく、信頼されたプラットフォームの一部として残ります。この整合性チェックは、動作を保証するものではなく、承認された配布物の外からダウンロードまたは読み込まれた任意のコードを証明するものでもなく、すべての内部的な影響を仲介するものでも、ネイティブのウォレットの承認に代わるものでもありません。

## スキルを書く

スキルは、指示ファイルと、それが参照するファイルを入れたフォルダです。

```text
my-skill/
├── SKILL.md
└── templates/
```

アプリ内で下書きし（`skill.create` は何も有効にせずにステージします）、検証してから、インストールして有効にします。意図的に三つの別々の手順にしているので、作成が暗黙のうちに動作を変えることは決してありません。カタログと作成の形式は、一般公開に向けてまだ最終調整中です。
