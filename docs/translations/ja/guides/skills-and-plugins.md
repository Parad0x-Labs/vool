# スキルとプラグイン

**スキル** は、繰り返し行う作業のための指示をまとめたものです。**プラグイン** は、ツール、モデルプロバイダ、またはアドオンのスキャナーを追加します。プラグインにスキルが同梱されていることもあります。

## 同梱と外部インストール

VOOLには、**ネイティブのスキルライブラリ**（アプリ本体に付属するスキル）と、現在のビルドでは **VOOL Database** プラグインが同梱されています。ご自身でスキルやプラグインをインストールすることもできます。

| | 同梱（VOOLに付属） | 外部インストール |
| --- | --- | --- |
| 保存場所 | アプリの中 | ご自身のプラグインフォルダ（設定ではなく、VOOLのプラグインのウィンドウから管理） |
| 更新 | アプリと一緒に | パックを更新したとき |
| 無効にできるか | アプリのウィンドウにはまだボタンがありません | はい（プラグインのウィンドウから） |
| 権限を付与するか | **いいえ** | **いいえ** |

どちらの入手元にも、次の二つのルールが当てはまります。

* **スキルは教えるだけで、決して権限を与えません。** スキルが宣言するツールは *絞り込み* のシグナル（そのワークフローのツール予算）であり、何かを許可するものでは決してありません。権限コントローラーはスキルを読みません。
* **インベントリは一つ。** コンソールに表示されるカタログと、ランタイムが読み込むパックは同じリストです。リストに表示されていても、読み込めるとは限りません。各項目は現在の状態（利用可能、無効、前提条件の不足、コントラクトが無効）とその理由を持っています。

## スキルを探す

「スキルとプラグイン」には、VOOL自身のスキルが最初に表示されます。**見る** には、すぐに使えるVOOLのスキルが75個あります。それぞれがアプリに同梱された指示のまとまりなので、「見る」はオンラインで調べずに一覧を表示します。そのうち22個は、選ばれたターンでVOOLのツール（メール、メモ、ファイル、PDF、ウォレットなど）を使います。スキルのツールは、リクエストに対してVOOLがすでに提供しているものを絞り込むだけです。オフのツールはオフのままで、すべての呼び出しはいつもどおり確認を求めます。そのスキルの **ソースと技術詳細** に、使うツールが表示されます。**スキルコーデックス** タブには、VOOLチームのスキルが最初に表示されます。スキルは、有効にする前にレビューしてください。

「見る」からスキルを追加する方法は、誰が作ったかによって異なります。

* **VOOLが作ったスキル**（上記の75個）：**このスキルを追加** を押します。VOOLは、ファイルが同梱されたものそのものであることをご自身のコンピュータ上で確認し、危険な指示がないかを読んでから、結果を表示します。キーは不要で、どこにも何も送信されません。ファイルが一致しない場合、VOOLはそれを拒否し、その旨を表示します。
* **ほかの作成者のスキル**（ほかの公開者のもの、または貼り付けたGitHubのリンク）：**ダウンロードしてスキャン** を押します。VOOLは公開スキルを固定のバージョンでダウンロードし、ご自身のコンピュータ上でチェックします。スキャナープラグインを有効にしている場合は、そのプラグインもスキルの内容を受け取り、そのレポートがVOOL自身のレポートの横に追加されます。結果を読んでから、スキルを追加するかどうかを選びます。どちらかのチェックが問題を報告した場合、VOOLは、そのバージョンについてリスクを受け入れた後でだけ追加します。スキャナープラグインが求めない限り、キーは必要ありません。

キーをまったく使わずに、チャットで自分のスキルを作ることもできます。[自分のスキルを作る](../../../guides/make-your-own-skill.md)を参照してください。

どのチャットでも尋ねることができます。*どんなスキルがある？* と聞くと一覧が表示され、*スキルを追加するには？* と聞くと両方の方法が説明されます。

## スキルをオンまたはオフにする

**スキルとプラグイン**、**マイアドオン**、**スキル** の順に開きます。各スキルには **オン** または **オフ** と、**有効化** または **無効化** のボタンが表示されます。オフにしたスキルは、もう一度オンにするまで、どのチャットでも使われません。そのファイルは保持されます。

**プラグイン** の下の **Built-in skills** カードには専用のボタンがありません。そのスキルは **スキル** で個別にオンまたはオフにしてください。

## どのスキルが回答に影響したかを見る

VOOLが回答を書く際にスキルの指示が使われた場合、回答の下の短い行にそのことが表示されます。たとえば **使ったスキル: Browser** です。これは、チャットを開いている間、回答の直後に表示されます。後で履歴から読み込まれた回答には、まだ表示されません。ほとんどの回答に付いてくる回答スタイルのルールは、そこには表示されません。

## VOOLの開発用のスキル

ライブラリには、VOOLチームがVOOLを開発するのに使うスキルも含まれています。コードレビュー、テストの実行、リリースのチェック、パイプラインの修復などです。これらはチャットにも「スキル」ページにも表示されず、普段の回答を左右することもありません。開発者は、`VOOL_DEVELOPER_SKILLS=1` を付けてVOOLを起動すると、これらを表示して使えます。

## 利用可能かどうかの状態

スキルは、種類の決まった理由とともに、利用不可と表示されることがあります。前提条件の不足（たとえば、データベースのスキルにはデータベースのプラグインが有効になっている必要があります）、このマシンで利用できない機能、無効なコントラクト、またはご自身で無効にした場合です。理由は項目ごとに表示されます。無効化は項目ごとに行われ、再起動後も維持されます。

## 重複する識別子

二つのパックが同じプラグインの識別子を宣言している場合（たとえば同梱のパックとインストールしたコピー）、同梱のものが **決定論的に** 残され、外されたコピーはカタログで報告されます。黙って隠されることは決してありません。

## 独自のスキルをインストールする

アプリ内のカタログからインストールするか、ご自身のプラグインフォルダをVOOLに指定します。パックには、そのツールを宣言するマニフェスト（`plugin.json`）が含まれています。権限の宣言が、宣言された動作クラスと一致しないマニフェストは、読み込み時に拒否されます。

{% hint style="danger" %}
検証の前に、パッケージ全体をレビューしてください。レビューは特定のバイト列についての根拠であり、安全の証明書でも、権限の付与でもありません。
{% endhint %}

## アドオンのプラグイン

**アドオン → マイアドオン → プラグイン** を開きます。ローカルフォルダ、または正確なコミットの公開GitHubフォルダをレビューします。インストールではパッケージ全体が取り込まれ、無効のままにされます。署名付きのストアのプラグインは既存のレジストリのチェーンを使い、同じく無効の状態でインストールされます。ツールやサービスを有効にする前に、アクセスシートを別にレビューしてください。サービスのキーを保存しても、リクエストは発生しません。接続のテストとモデル一覧の更新は、明示的な操作です。

無効にするとツールが取り除かれ、実行中の呼び出しが止まります。アンインストールでは、まず無効にしてから、所有するファイルとスクラッチを削除し、既定では保存されたキーを削除し、履歴は残します。アップデートと再インストールには新しいレビューが必要で、無効の状態から始まります。別のリポジトリや公開者からのアップデートでは、保存されたキーは引き継がれません。UsePodとEyebrowはもうVOOLの一部ではなく、VOOLはどちらのプラグインも提供していません。保存されたUsePodやEyebrowのキーはこのコンピュータに残り、VOOLはそれを使いません。そのことは、通知を閉じるまでアドオンに表示されます。UsePodのモデルを使っていたチャットでは、アップグレード後にモデルが選択されていない状態になり、それらのチャットでは「自動」がクラウドのモデルに切り替えることはありません。そのことは、通知を閉じるまで表示されます。

[プラグインの作成](../../../guides/plugin-authoring.md)と[アドオンのチェック](addon-security.md)を参照してください。

## パッケージ全体の承認


検証は、ハンドラの実行ファイル、同梱されたライブラリ、依存関係のロック、参照、アセット、実行可能モードのビットを含め、パッケージのすべてのファイルとディレクトリを対象にします。これらのいずれかを追加、削除、名前変更、変更すると、承認は無効になります。シンボリックリンク、ハードリンク、特殊ファイル、特権モード、不安定な読み取り、サイズが大きすぎる配布物は拒否されます。現在の取り込みの上限は、4,096項目、ファイルあたり64 MiB、パッケージあたり128 MiBです。パッケージの中に、無視されるキャッシュや状態のディレクトリはありません。

以前に保存された、メタデータだけの承認では、このバージョンのパッケージは有効になりません。配布物全体をレビューし、改めて明示的に検証してから、有効にしてください。アップデートは、検証して有効にするまで無効のままです。承認が黙って移行されることは決してありません。管理されたアドオンでは、古いレシートが配布物全体を拘束していない場合、認証された新しいストアのレビューも必要です。通常の検証では、そのレシートの代わりにはなりません。

`requires` は、インストール済みのプラグインの依存関係を指定します。検証では、それらの再帰的な承認ダイジェストを固定します。各依存関係は、すでに検証されて有効になっている必要があります。依存関係が変更、更新、無効化、取り消しされると、それに依存するものは、キャッシュされたツールを通じた場合も含めて利用できなくなります。受け入れの際には、ハッシュの計算の後で、取り込んだ閉包全体について有効の状態と取り消しの状態を再確認します。依存関係を再検証しても、その新しいバイト列が親に対して黙って承認されることはありません。すべての親もレビューして再検証してください。各 `approval_digest` は、そのパッケージのダイジェストと依存関係の承認を拘束するため、推移的な依存関係が変わると、親自身のファイルが同一のままでも、その承認が変わります。循環する依存関係の承認は有効になりません。依存関係の閉包は64パッケージまでに制限されています。

登録された各呼び出しは、ライフサイクルの状態をもう一度確認し、パッケージとその固定された依存関係の閉包を、読み取り専用の非公開コピーとして取り込みます。ツールのコントラクトは、取り込んだマニフェストと一致する必要があります。登録されたハンドラは、その取り込んだコピーから起動するため、取り込みの後にソースを編集しても、そのハンドラや同梱のファイルを置き換えることはできません。実行の観測記録には、パッケージ、再帰的な承認、依存関係のダイジェストが含まれます。登録されたパッケージには、ローカルの低レベルの呼び出し元がより弱い上書き設定を選んだ場合でも、実際のカーネルによる隔離が必要です。リンクをたどらない安全な記述子の取り込み、またはカーネルによる隔離ができないホストは、登録されたパッケージを拒否します。呼び出しのタイムアウトは1〜300秒の範囲に制限されます。呼び出しが所有するプロセスグループは、実行用のコピーが削除される前に停止されます。

永続的な出力、キャッシュ、ログは、実行可能なコードの隣ではなく `PLUGIN_SCRATCH` に保存してください。読み取り専用のツールには、書き込みの許可は与えられません。その他のツールはスクラッチに書き込めますが、自分の実行用のコピーは変更できません。`VOOL_PLUGIN_DEPENDENCIES` は、宣言された依存関係の識別子から、取り込まれた依存関係のディレクトリへのJSONのマッピングです。その他のサードパーティのライブラリとそのロックは、パッケージの中に同梱してください。ロックファイルだけでは、外部の環境を証明できません。ランタイムのインタプリタとシステムライブラリは、レビュー済みのサードパーティのパッケージのバイト列として表されるのではなく、信頼されたプラットフォームの一部として残ります。この整合性チェックは、動作を保証するものではなく、承認された配布物の外からダウンロードまたは読み込まれた任意のコードを証明するものでもなく、すべての内部的な影響を仲介するものでも、ネイティブのウォレットの承認に代わるものでもありません。

macOSでは、プラグインのコードはmacOSのサンドボックスの中で実行されます。キーは、ハンドラの非公開の入力を通じてだけ渡され、環境変数には決して入りません。Macでは、プラグインのコードを含め、同じユーザーのどのプログラムでも、ほかのプログラムの開始時の環境を読めるためです。環境にキーが必要な接続サーバーは、ご自身で用意する任意の隔離されたLinuxランタイムの中でだけ実行されます。VOOLがVMを起動したり、イメージをダウンロードしたりすることは決してありません。それがない場合、そのプラグインはオフのままで、その理由を表示します。Linuxでは、非公開のプロセス名前空間と `/proc` を含め、bwrapを使います。

macOSでは、ネットワークを宣言したツールが接続できるのは、VOOLが呼び出しごとに起動する非公開のプロキシだけで、そのプロキシは宣言されたホストにだけ接続します。Linuxと隔離されたランタイムでは、プラグインのプロセスはネットワークを使えません。ネイティブのプロバイダとスキャナーのリクエストは、どのプラットフォームでも、宣言されたホスト向けの別のHTTPS通信路を使います。
