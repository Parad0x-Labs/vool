# アップデートと移行

## アップデートの仕組み

0.7.5以降、VOOLは自動でアップデートします。「自動でオンラインに接続」がオンなら、お知らせを表示し、ワンクリックで新しいバージョンをインストールします。Macで0.7.4または0.7.3からアップデートする場合は、「自動でオンラインに接続」（設定 > プライバシーと権限）をオンにして、「更新を確認」を一度押してください。Linuxで0.7.4以前、またはMacで0.7.2以前からの場合は、0.7.7をダウンロードして、現在のバージョンに上書きインストールしてください。チャットと設定は、アプリの外にあるプロファイルに保存されています。

「自動でオンラインに接続」がオンの場合、VOOLは起動時と一日一回、新しいバージョンを確認し、確認ボタンを押さなくてもお知らせを表示します。オフの場合、VOOLは何も取得せず、ヘッダーに **更新の確認はオフ** と表示されます。

署名されたアップデートパッケージは、自動ロールバック付きの検証済みのパイプラインで実行されます。

1. **ダウンロード** — 署名されたマニフェストに照らして検証されます。
2. **段階的インストール** — 新しいバージョンが、古いバージョンの隣にインストールされます。
3. **移行** — データが新しいストアのバージョンに移行されます。移行に失敗した場合、データは以前のバージョンに戻され、アプリはそのバージョンで再起動します：*「Your data was restored to the previous version.」*
4. **ヘルスチェック** — 古いバージョンを退役させる前に、新しいバージョンが動作できることを証明する必要があります。
5. **切り替え** — アトミックに行われます。以前のバージョンは、ロールバック先として残されます。

Linuxでは、tarball版も同じ方法でアップデートします。新しいバージョンは実行中のバージョンの隣にインストールされ、`current` が一度に切り替わります。新しいバージョンが正常でない場合、VOOLは自動で以前のバージョンに戻します。手動の **Roll back** は、Macとソースからのインストールでは提供されていますが、Linuxのtarball版ではまだ提供されていません。

いずれかの段階が失敗した場合、アプリは元のままです。失敗のメッセージには段階の名前（`verification_failed`、`insufficient_disk_space`、…）が示され、各段階には専用の復旧の文があります。

## データの互換性

* プロファイル、チャット、レシート、設定はアプリのバンドルの外にあるため、アプリを置き換えても、データが置き換えられることは決してありません。
* ローカルのストアは、**ダウングレード** での読み込みを拒否します。新しいVOOLが書き込んだデータベースを、古いVOOLが黙って読むことはありません。そう伝えて拒否します。未知のストアの構成を推測すると、データが壊れてしまうからです。新しいデータを読むには、新しいバージョンをインストールし直してください。
* アップデートでインストールされたファイルとアップデートの状態そのものは、レシートとともにプロファイルに記録されるため、「どのバージョンが自分のデータに触れたか」に後から答えられます。

## ベータチャネル

現在のリリースラインは **ベータ版** です（[リリース状況](../trust/release-status.md)を参照）。アップデートは固定された発行元の鍵で署名され、インストールの前に確認されます。macOSアプリ自体はアドホック署名で、公証を受けていないため、新しいバージョンを初めて起動するときに、macOSが確認を求めることがあります。
