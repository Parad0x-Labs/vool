# 構成

## 保存場所

VOOLは、設定、チャット、メモリー、記録を、一つのランタイムホーム（runtime home）に保存します。

| インストール | ランタイムホーム |
| --- | --- |
| macOSアプリ | `~/Library/Application Support/VOOL/runtime` |
| Linuxのtarballとソースからのインストール | `~/.vool_runtime` |
| Windows（試験的、ソースから） | `%LOCALAPPDATA%\VOOL` |

VOOLを起動する前に `VOOL_HOME` を設定すると、代わりにそのフォルダが使われます。起動時のログには、使用中のホームが出力されます。

キーが設定ファイルやログに書き込まれることは **ありません**。キーは、このランタイムホームの中にある別の認証情報ファイルに暗号化して保存され、そのファイルはご自身のユーザーアカウントだけが読めます。Macで、VOOLがすでにmacOSのキーチェーンに保存していたキーは、そのまま残ります。[セキュリティモデル](../trust/security.md#キー)を参照してください。

## 設定

設定は、アプリの **設定** で変更します。VOOLに何を許可するかを決める設定は次のとおりです。

* **モデル** — 有効なモデルです。ターンがローカルかクラウドかは、これで決まります。
* **ワークスペース** — チャットが作業するプロジェクトフォルダです。VOOLがアクセスできるその他のフォルダについては、[ワークスペース](../concepts/workspaces.md)を参照してください。
* **動作モード** — ここではなく、メッセージ欄の横のメニューで選びます。「手動」はすべての変更の前に確認し、「自動」は日常的な編集やコマンドを実行させますが、削除、上書き、インストール、支出、設定の変更は引き続き確認します。[権限](../concepts/permissions.md)を参照してください。
* **ウェブアクセスと暗号資産** — どちらも、ご自身でオンにするまでオフのままです。

VOOLには、製品テレメトリの設定はありません。製品テレメトリを一切送信しないからです。

## リセット

VOOLを終了し、ランタイムホームを別の場所に移します。ワークスペースのファイルには手を加えません。VOOLは新しいプロファイルで起動し直します。保存していたキーも一緒に移動するので、**設定 → APIキー** でもう一度追加してください。macOSのキーチェーンに保存されているキーは、キーチェーンアクセスで削除するまでそこに残ります。
