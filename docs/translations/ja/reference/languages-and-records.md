# 言語、アクセシビリティ、記録

## インターフェイスの言語

VOOLのインターフェイスは、複数の言語で利用できます。新しい文言は、翻訳が追加されるまで英語で表示されることがあります。言語の選択は、表示だけの問題です。権限の判断、支出の権限、エラーコードは **設計上、言語に依存しません**。翻訳されたエラーメッセージが、英語のオーソリティが決めた内容を広げたり狭めたりすることは決してありません。

## アクセシビリティ

* 主な操作の流れには、キーボードショートカットがあります（[キーボードショートカット](shortcuts.md)を参照）。
* ドキュメントとアプリの画面には、ライトとダークの表示があり、システムの設定に従いつつ、手動で切り替えることもできます。
* エラーは、色だけでなくテキストで示されます。破壊的な操作には、一度の誤クリックで済むのではなく、必ず明示的な確認が必要です。

## アクティビティ

アクティビティビューは、VOOLが行ったことの完全な履歴です。入力と結果を含むツール呼び出し、あなたが許可または拒否した承認、レシート付きの支払いが含まれます。ガードによって止められたターンには、停止とそのガードが表示されます。拒否は記録されるイベントであり、何もなかったことにはなりません。

## レシート

お金と支出に関わる操作は **レシート** を書き込みます。何が提案され、何が承認され、何が送信され、何が確定したかです。結果が不明なものは不明として記録され、成功や失敗として語られることは決してありません。これにより、*「check its status before retrying」* が実際に行動できるものになります。レシートが、支払いが実際にどの状態にあるかを教えてくれます。

## モデルの検証状況

VOOLは、モデルが **言った** ことと、ランタイムが **証明した** ことを区別します。

* ツールの結果は、実行記録とともに記録されます。ファイル、支払い、データについての回答の主張は、それらの記録に結び付けられ、裏付けのない主張は表示されません。
* レシートには、検証の状態が含まれます。このビルドでレーンが試験的または検証できない場合、その状態は、証明があるかのように示すのではなく、そのことをはっきり示します。

概念については[レシート](../concepts/receipts.md)を、失敗がどのように分類されるかについては[エラー](errors.md)を参照してください。
