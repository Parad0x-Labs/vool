# Proposed trusted admission service

This is an activation contract. Scanner adapters, disposable workers, protected
check identities, independent signing custody and a publisher receipt service
are not activated by these documents or repository blueprints. Fixture reports
and signatures verify protocol mechanics; they establish no production scanner
execution, isolation, quality or custody.

The existing review verifier, offline admission signer and `TrustedCatalog`
remain the authorities. No new database flag or website response can approve a
package. A raw report hash establishes consistency, not that a scanner ran.

## Required-check authenticity

The blueprint's candidate-run `Registry advisory preflight` workflow is
advisory. A pull request can change the workflow that checks its own content;
read-only permissions, a trusted tooling checkout and CODEOWNERS do not
authenticate the resulting green check. Do not configure this candidate job
as the admission authority.

Require an externally operated GitHub App admission check with that exact App
as the expected source. Its protected control plane reads the candidate as
bounded inert data, authenticates actual execution evidence and binds its
verdict to the exact commit and artifact. A same-named candidate check cannot
substitute. Apply and inspect the branch settings; a blueprint alone supplies
no enforcement. [GitHub expected check source](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches#require-status-checks-before-merging).

An alternative requires an independently protected workflow plus a verifier
that authenticates its pinned revision, workload identity, repository, event,
target commit and artifact. Candidate files, writable caches and outputs
cannot supply its tools, policy, roots or signers. A privileged control plane
must not checkout or execute candidate code. [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use).

## Immutable inputs and observed execution

The protected scheduler independently computes complete artifact hashes,
length, inventory and native digest. It freezes the recursive approved
dependency closure, refuses cycles/conflicting approvals and enforces the
existing 64-node limit. A server-issued invocation binds stage, expiry,
artifact identity, policy descriptor hash, separate exact target-matrix hash,
source publication, released VOOL build/platform, dependency graph and pinned
scanner/prompt/configuration/image hashes.

Private prepublication requires archive and secret checks before consent.
Final admission requires all eleven policy checks, including two independently
operated instruction reviews and actual compatibility on every exact released
target. Private reports cannot be retargeted as final evidence. Missing,
skipped, unsupported, truncated, timed-out, contradictory, stale or future
results and every unresolved finding, including warnings, refuse admission.

Disposable workers receive read-only hash-verified input and fixed trusted
tools. They receive no user profile, provider/signing credentials, host paths,
Docker socket, production database, sibling outputs or repository-write token.
Enforce measured operator-approved CPU/time/process/disk/output/network bounds.
Static intake executes no candidate content; dynamic compatibility requires
disposable isolated environments under existing native confinement.

A trusted supervisor observes process identity, mounted inputs, start/end,
exit status, coverage, resource/truncation status and raw output. It attests
the exact invocation/context and report hashes. Candidate JSON, a nonce echo
or a claimed `complete` field is insufficient. The collector independently
normalizes the observed results and preserves failed attempts. Retry only a
diagnosed infrastructure transient, under a new linked invocation.

## Independent signing and publication

Review signers use separate protected principals and custody from submitters,
candidate CI, workers and the web service. Each custodian independently verifies
authenticated supervisor identity, immutable context, raw outputs and complete
coverage before threshold signing. Different key IDs in one candidate-accessible
environment do not establish independence. Offline admission/root/catalog roles
retain their existing separation, thresholds, freshness and rollback protection.

Export currently verifies signed evidence and transactionally rechecks live
account ownership, ready state, consent and unchanged artifact/review bytes
before returning an outbox snapshot. It cannot recall an already-exported file.
Activation requires a short-lived single-use publisher receipt bound to exact
submission/account/artifact and current consent, rechecked and consumed before
permanent publication. Crash recovery must inspect exact remote bytes before
retrying a possible write. The current worker exports files and opens no PR.

Final publication evidence binds actual immutable GitHub bytes and commit.
Failure reports remain author-private and redacted; suspected secrets are
discarded from payload storage. Configure restricted raw-output retention,
encrypted backups and tested deletion/restore behavior. Permanent namespace
reservations retain only the name, not deleted account/provider identifiers.

## Activation acceptance

Verify real scanner adapters/versions, approved platform matrix, protected
check source/workload identities, independent key custody, trust anchor,
provider registration, storage/retention/restore and bounded requests. Run the
complete fresh-package chain and failures: no-run fabricated green, unauthorized
candidate-CI signer, altered raw output, retargeted release/dependencies,
interrupted scanner, expired evidence, account deletion after export, namespace
reclaim, signer revocation and installed-file tampering. Prove native budget,
currency, permission and approval refusals for direct, indirect and non-English
instructions. Local fixtures cannot satisfy this production acceptance.
