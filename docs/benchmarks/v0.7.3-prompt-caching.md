# Prompt caching and cost: planned for VOOL 0.7.6, not released yet

**Not released yet.** Prompt caching is planned for VOOL 0.7.6, not released yet. In 0.7.5 it is off. Everything below was measured on a
development build in October 2026.

We sent the same 44 messages to VOOL on three models, with caching on and off, and to Claude in Claude
Code. We compared what each setup cost and how many answers were right.

**Who ran it.** Claude, Anthropic's AI model, built this test, ran it on the team's Mac and wrote this
page for the VOOL team. Claude Code, the comparison here, is Anthropic's own coding agent, and it scored
highest. Every number is in [`prompt-caching-results.json`](prompt-caching-results.json).

## In plain words

| Setup | Cost per 1,000 messages | Answers judged right |
| --- | --- | --- |
| Claude in Claude Code | $31 | 97% (85 of 88 points) |
| Claude in VOOL, caching off | $15 | 51% (45 of 88) |
| Claude in VOOL, caching on | $13 | 57% (50 of 88) |
| Kimi K3 in VOOL | $13 | 58% (51 of 88) |
| GPT-4.1-mini in VOOL | $1.13 | 59% (52 of 88) |

* **Where the savings are.** VOOL costs about half what Claude Code does for the same messages, because
  it sends Claude far less text each time. Caching takes about 10% off on top of that. GPT-4.1-mini in
  VOOL costs about a tenth of a cent per message.
* **Where VOOL loses.** On plain chat every setup gets almost everything right. VOOL's low scores come
  from questions about files in a folder and a long pasted document. Those are VOOL problems, listed
  below, and the fixes are planned for 0.7.6, not released yet.
* **Kimi K3 and GPT-4.1-mini without VOOL were not tested.** Claude Code only runs Claude, so Claude is the
  only model with a with-and-without comparison.

![Caching: Claude charges a tenth of the price for text it has already seen](charts/prompt-caching-how-it-works.svg)

VOOL marks its setup and rules as the part to save, so each later message pays full price only for the
chat and the new question.

## What was tested

* **Three tasks, each run twice:** a long pasted document with questions about it (16 messages, 32
  points), a folder of files with questions about them (12 messages, 24 points) and a quick dinner chat
  (16 messages, 32 points). 44 messages and 88 points per setup.
* **Six setups, all through OpenRouter:** Claude Code with Claude Sonnet 4.5 and its own caching; VOOL with
  Claude Sonnet 4.5 and caching off, on the system prompt, or on the system prompt and the chat history;
  VOOL with GPT-4.1-mini and with Kimi K3, both with the provider's automatic caching.
* **Grading:** GPT-4.1-mini graded every answer blind against written reference facts, 0 to 2 points each.
* **Two runs.** Run 4 tested all six setups. Run 5 tested the five VOOL setups again, this time sending the
  whole chat on every message as the VOOL app does. Run 4 sent VOOL only the latest message.

## Cost

![Claude cost about twice as much in Claude Code as in VOOL](charts/prompt-caching-cost.svg)

![Claude Code sent 13 times as much text as VOOL for the same 44 messages](charts/prompt-caching-tokens.svg)

Claude Code sends a fixed setup of about 40,000 tokens with every message: about 53,000 prompt tokens per
message, against about 4,100 for VOOL. It caches 94% of that, but the 94% is a discount on text VOOL
never sends.

## Caching saving

![One cache mark on the system prompt cut cost by 9.5% and 9.6% in two runs](charts/prompt-caching-saving.svg)

The saving is small because Claude Sonnet 4.5 only caches a prompt start of 1,024 tokens or more, and most
VOOL follow-up messages sent 600 to 2,000 tokens. Nearly all cache hits came from the two large first turns:
the document turn (about 44,000 tokens over 11 model calls) and the first files turn (about 9,000). A second
cache mark on the chat history writes cache that is rarely read, so it saves less; the plan for 0.7.6 is to keep only
the system-prompt mark. An earlier lab test showed 61%, but it used 9 large synthetic requests and does not hold
for real chats.

## Quality

![Plain chat is level; documents and files hold the whole gap](charts/prompt-caching-quality.svg)

Where VOOL lost points, read from its answers:

| Problem | What happened | Planned for 0.7.6 |
| --- | --- | --- |
| Does not look in the folder on its own | Asked about "the garden" or "the controller log", VOOL said there was no such file. Claude Code found and read them. | Look through the chat's folder before saying a file is missing |
| Raw file, then a wrong total | VOOL pasted the expenses file as it was, then got one person's total wrong (635.70 instead of 416.70) | Answer the question asked and compute totals with a tool |
| Pasted document dropped | Chat history is capped at 5,000 characters, so a long pasted document was gone after the first message | Long pasted text kept as a chat document, as attached files already are |
| Wrong route | A pasted document went to saved-chat search, and one question went to web lookup with web off | Route these cases correctly |
| Empty answers | 2 to 4 messages per setup ended with no usable model answer, and VOOL then declined related questions | Retry instead of giving up |

Sending the whole chat each message (run 5) raised VOOL on Claude only from 41-43 to 43-50 points, so the
test setup was not the cause of the gap.

## What limits these numbers

* **Small sample.** 3 tasks we wrote, 44 messages per setup, two runs. Score differences of a few points
  are within chance: between the three VOOL-on-Claude setups they moved in different directions from run to
  run, so caching did not change quality either way.
* **One judge.** GPT-4.1-mini is also one of the models tested and may favour answers like its own. No second
  judge checked it.
* **Different runs.** Claude Code ran in run 4 only. VOOL's figures in the plain-words table are from run 5;
  in run 4 VOOL scored 41 to 48.
* **Different tools.** Claude Code read the folder with its built-in file tools. VOOL ran in its default auto
  mode with web lookups off. That is the product difference being measured, not a handicap we added.
* **Same Claude on both sides.** Claude Sonnet 4.5 through OpenRouter at October 14-15, 2026 prices. Prices
  and models change.
* **Money.** Costs come from each answer's billed usage; in run 4 they matched the OpenRouter key meter within 2.7%. An
  early counting mistake was fixed before these numbers: Claude Code reports a running total for its session,
  which the first report counted as the cost of each message.
* **Answers without the model.** In every VOOL setup, VOOL answered 2 messages itself ("web lookups are off");
  they count as wrong.
* **Speed** was level: a median message took 7.4 to 8.4 seconds on VOOL with Claude and 8.0 seconds on Claude
  Code.
