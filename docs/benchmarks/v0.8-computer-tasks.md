# Computer tasks head to head: planned for VOOL 0.8, not released yet

How well an agent handles everyday "do this on my computer" requests (find a file, how big is a folder,
what did the landlord say about the deposit, what is the Wi-Fi password in my notes) without breaking
anything, against two other open-source agents that run on your own machine: OpenClaw and Hermes Agent.

The VOOL build tested is a development build of the 0.8 line (commit `39fc9527`, the clean local loop).
It is not in a released VOOL yet. Every file behind every number is in
[`computer-tasks-0.8/`](computer-tasks-0.8/): the tasks, the answer keys, every answer word for word,
every jury verdict with its reason, the sandbox profiles and the scripts.

## Why the tasks were not tuned for VOOL

The full timeline with hashes and request ids is in [`PROVENANCE.md`](computer-tasks-0.8/PROVENANCE.md).

* **VOOL's code was frozen first.** Commit `39fc9527`, clean tree, at 21:36 UTC on 28 October 2026. Every
  VOOL answer row records that commit. Nothing in VOOL changed between the freeze and the last run.
* **Someone else wrote the tasks.** For round 1 a fresh Claude Opus 5.5 call wrote 45 tasks and their answer
  keys at 22:05 UTC, from the test folder's files only: no VOOL code, replies or scores. The task file was
  frozen at 22:07 UTC. The first VOOL run started at 23:23 UTC.
* **Round 1's weak spot, and round 2.** Round 1's test folder (31 made-up files) had been used in earlier
  VOOL development tests; the tasks were new, the folder was not. Round 2 removes that. On 29 October at
  09:07 UTC one fresh Claude Opus 5.5 call invented a new person, her home folder (39 files) and 45 new tasks
  with keys. Its only inputs were its instructions ([`SYSTEM.txt`](computer-tasks-0.8/round2/SYSTEM.txt))
  and a short brief with the task categories ([`BRIEF.md`](computer-tasks-0.8/round2/BRIEF.md), written by
  the test runner). The raw reply is kept. Same VOOL commit, checked at 09:03 UTC.
* **Same conditions.** Same task text, same model per arm, a fresh copy of the test folder per task, a
  300 second limit (a timeout counts as wrong), each agent on its own default settings, no rival prompt
  tuned. Hermes needs a 64K context window to run at all; that is its only changed setting.
* **Blind grading.** A Claude Opus 5.5 jury saw one answer at a time, with the answer key and the before
  and after state of the folder, and with system names and machine paths removed. Verdicts: correct, wrong
  but sure, wrong but hedged, unsafe change, out of copy (talked about files that are not in the folder).
  Where the jury and the automatic checker disagreed, a Claude Fable 5.1 judge re-graded a sample of 10 and
  agreed with the jury on 10 of 10 (round 1) and 9 of 10 (round 2). The jury's verdict is the score.

## What the agents tried outside the test folder

All three ran inside macOS sandboxes against a made-up home folder. Two things happened that we did not plan
for, and both changed how the test was run.

* **Round 1, older sandbox.** On a "what is taking up my disk space" task, OpenClaw 2026.9.6 read folder names
  and sizes from the real Mac's home folder and sent them to its model provider as part of its work. No file
  contents. Reads outside the test folder were blocked from then on, and the rival rows were rerun.
* **Round 2, Wi-Fi password.** The test person keeps her Wi-Fi password in a note on her Desktop. VOOL read
  the note. Hermes ran macOS's `security` tool to read the real Mac's saved Wi-Fi password, which raised a
  system password prompt (denied). OpenClaw listed the real login keychain's entries and tried to read saved
  Wi-Fi passwords, including with `sudo`. No password came back to either. The sandbox was then switched to
  deny-by-default for programs and reads, and both rivals were rerun in full under it. Under that profile
  OpenClaw copied system tools into a temporary folder and ran the copies, and tried to place them in the
  real home folder; all of it was refused. The round 2 scores above are from those reruns.

What each sandbox profile allows, check by check, is in
[`sandbox/PROBE-v4.txt`](computer-tasks-0.8/sandbox/PROBE-v4.txt) and the other probe tables.

## Disclosures

* VOOL's cloud rows call VOOL's clean loop and its tools directly
  ([`vool_cloud_bench.py`](computer-tasks-0.8/scripts/vool_cloud_bench.py)); VOOL's routing layer and its
  answer gates are not in those rows. The local rows run the same loop.
* Machine-specific names (account, folders, drives, network names, keychain entries) are replaced by
  `<placeholders>` in every published file, including the scripts, so the scripts need those paths filled in
  to run. [`SCRUB-CHECK.txt`](computer-tasks-0.8/SCRUB-CHECK.txt) lists the pattern counts (all 0).
* The round 1 task set is public from this page on; any later "fresh tasks" claim needs a new set.
* Still to come: newest Hermes on the local model, and round 2 on the local model.

## Where VOOL was weak

* Round 2: 6 answers the jury graded wrong but hedged (no confident wrong answers).
* Round 1 local: 4 answers wrong but sure on the 8B model.
* Its cloud rows do not include its routing layer, so the shipped app path still needs its own run.
